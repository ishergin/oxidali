Device detail — the six tabs

One tab is one fetch. Overview needs only the device core (GET …/physical-devices/{short}); every other tab adds exactly the attribute sections it renders (?sections=…), and Identity additionally asks for bank coverage. The screen used to pull all twelve sections plus bank coverage every 5 s for whichever card happened to be on screen — 7.7 KB per device per poll, of which the operator was looking at one card.

Unread sections

The dot says the controller holds nothing for that tab yet — no read has landed, so the panel behind it will be an empty state rather than data. Distinct from a gear that answered “not implemented”, which is a value the panel renders as a not implemented chip. Faint, never warn: unread is the ordinary state of a section nobody has asked for.

Anchors, not buttons

Each tab is an <a href="#/devices/4/energy">, the same shape the scene selector uses. The tab is then linkable, survives a reload, and comes back from a browser Back — and the fetch for a tab’s sections hangs off the route rather than off local component state, so there is one place that decides what is being requested.
