One rule at a time, one document underneath. The device stores the operator's source byte-for-byte — comments included — so the rule list and the rule's tab are a view, not a second format: saving splices the edited rule back and writes the whole document under one revision. Whole document is the same text unscoped, for the edits a single rule cannot express (a def block, reordering, a comment header). The parse state, the revision and the size against the device's ceiling sit in the editor bar because they describe the text being edited.

Names complete from the registry. Inside the first string of lamp(", group(", input(" and hcl.enable(" / hcl.disable(" the editor lists the controller's names — prefix matches first, then names containing the text; Enter, Tab or a click inserts the name with its closing quote. A name a rule string cannot hold (a quote, a line break, over 48 bytes), or one several entries share, is offered by its id. The list reads the caret's surroundings and nothing more: what the text means is the device parser's call.
