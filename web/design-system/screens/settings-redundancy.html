The unit driving the bus

Redundancy

Settings

A second controller on this segment, silent while the first is alive. The wire decides which is which; the network never does.

Role

Enabled
Off: nothing probes, nothing takes over, and this controller behaves exactly as a single controller always has.
This controller is a standby
DiiA 351 §5 gives the arbitration algorithm to type B alone. On: this unit asks. Off: it is a primary — dominant, never asks and never stands down of its own accord.

Detection

Probe interval, ms
How often a standby asks the segment whether it still has an owner. 250–60000. One probe is ~38 ms of wire at the lowest priority, so 250 ms is already about 15 % of the bus.
Take the bus after
Consecutive unanswered probes. Never one by default: a missed query is indistinguishable from a NO (102 §3.13 Note 1), so a single lost frame must not move the bus.
Worst-case detection
Misses × interval, plus one exchange.
0.86 s
Peer short address
The peer’s Part 103 control-device address (0–63, empty = none). Needed only for a planned switchover; the probe is broadcast.

Configuration pull

Peer API address
http://host[:port] of the other controller. A standby pulls names, bindings, schedules and rules from it every 30 s. Empty = no pull, and the standby owns an installation it knows nothing about.
Direction
Only a passive unit pulls, and it never pushes. The active controller is the source, so a takeover cannot overwrite the peer with a copy of itself.
Passive pulls from the active one.
