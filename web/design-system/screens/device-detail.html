2026-09-01 — the override rows join their siblings

The two override rows put their control cluster on a line of ITS OWN — label above, controls below, left-aligned — while every other row in the same card is label-left, value-right. So the Information card read as three kinds of row: Name and Random address right-aligned, the two override rows as left-aligned two-liners, and Declared types wedged between them, right-aligned again. That is the owner's "не правильно выровнены Device type override / Color type override".

The reason it was stacked has since gone. It was written when the shell was capped at 1240 px, leaving these cards ~330–480 px wide; the shell now runs to 1680 px and .grid2 collapses to one column below 900 px, so the narrow case is a full-width card. The cluster keeps its two FIXED slots (112 px select, 168 px badge) and simply wraps inside its own value slot when it has to — which is what keeps the two override rows aligned with each other, since a select sizes to its widest option and a badge to its text.
