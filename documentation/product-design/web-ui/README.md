# Web UI

Встроенное SPA контроллера: как оно устроено, правила, которые соблюдает каждый
экран, и индекс экранов со спецификациями.

**Границы:** визуальный дизайн — проект Claude Design «dali2rust Web UI» и его зеркало
`web/design-system/` (карточка на каждый экран и компонент); код — `web/app/`
(рецепт добавления экрана — `web/app/README.md`); контракт API —
[`../rest-api/README.md`](../rest-api/README.md); сборка бандла, зеркало в прошивке и
выгрузка карточек —
[`../../architecture/10-build-release-and-tooling.md`](../../architecture/10-build-release-and-tooling.md).

## Как устроено

- Preact, Vite, TypeScript; hash-маршрутизация без библиотек; состояние — сигналы.
  Типизированный клиент (`web/app/src/api/`) зеркалит DTO сервера; при расхождении
  прав код сервера.
- Данные читаются по REST; одно WebSocket-соединение приносит изменения, а опрос —
  запасной путь ([`websocket.md`](websocket.md)).
- Контроллер отдаёт бандл из флеша, поэтому изменение UI доходит до устройства только
  с перепрошивкой.
- Тёмная и светлая темы на общих токенах дизайн-системы; по умолчанию — тёмная.

## Правила каждого экрана

- **Цвет.** Янтарный акцент — только состояние ламп и уровни; `warn` — «грязно»
  (desired ≠ applied); моноширинный — адреса и hex; служебные подписи бледные и мелкие.
  Новый класс получает стиль в том же проходе, что и разметка.
- **Непрочитанное не рисуется нулём.** «Не читалось», ответ прибора «0 / нет», MASK,
  TMASK и «вне диапазона» выглядят по-разному, а не как ноль, «нет» или пустота.
  Переключатель над непрочитанным значением не угадывает положение и предлагает оба
  действия явно. Селект над сохранённым значением всегда содержит само значение, даже
  вне допустимого набора, и пункт «не прочитано» для непрочитанного: иначе
  контролируемый `<select>` молча показывает вариант, которого на приборе нет.
- **Таблиц стандарта в UI нет.** То, что классифицирует прошивка (конфигурация bus
  unit, валидность полей Part 251), приходит в ответе классифицированным; экран только
  называет значения. Имя продукта по GTIN из базы продуктов
  (`web/app/public/dali-products.json`; в репозитории она пустая, база DiiA не
  распространяется) — лишь бледная подпись без провенанса: имя устройства пишет один
  писатель — оператор.
- **Черновик побеждает опрос.** Экраны перерисовываются при каждом обновлении данных,
  поэтому поле ввода над опрашиваемым значением держит черновик: `EditableText` — для
  значения, которое перебирают (коммит сырой строки при потере фокуса, разбор и
  зажим — в `onCommit`, а не на каждую клавишу); `EditableName` — для имени, которое
  решают (коммит только по ✓/Enter, обрезает пробелы, пустое не принимает). Экраны
  настроек копят правки в черновике до Apply/Discard; кнопка Apply неактивна без
  изменений.
  - `EditableText` вызывает `onCommit` на каждом неотменённом blur, в том числе без
    правки: запись, равную серверному значению, отбрасывает вызывающий.
  - Ползунки уровня и CCT держат черновик, пока опрошенное значение не станет равным
    ему, а не до следующего опроса: опрос посреди перетаскивания или до подтверждения
    записи иначе отбрасывает бегунок назад.
  - Кнопки внутри поповера переименования (✓/✕ и переключатель рядом) гасят
    `mousedown`: иначе blur поля закрывает поповер раньше, чем клик дойдёт до кнопки.
- **`202` — не «записано».** Разрешившийся трекинг операции не значит, что запись
  легла: перед тем как применить результат, перейти к нему или выбросить черновик,
  экран проверяет `opCommitted`.
- **Матрицы групп и сцен.** Apply стартует только после того, как сохранение матрицы
  закоммитилось: оркестратор разворачивает diff из реестра, а не из запроса. Панель
  Apply считает только несохранённые правки оператора (правка, вернувшаяся к серверному
  значению, выбрасывается); расхождение desired ≠ applied на приборе — отдельный чип
  `warn`, который с правками не складывается и который Discard не очищает.
- **Карточка устройства**: вкладка запрашивает только свои секции атрибутов, но всегда
  вместе с `common_102` — полоса управления стоит над вкладками и берёт кнопки Min/Max
  из `min_level` / `max_level`. Пока идёт discovery, запущенный с экрана устройств, экран
  объясняет, что команды уровня и цвета ждут его конца: скан шину не уступает, и `504`
  в это время законен.
- **Цветовой контрол не шлёт `power`**: цвет у выключенной лампы подготавливается, а
  не включает её.
- **Счётчики** (Stats и Diagnostics): абсолют и дельта к прошлой выборке по правилам
  чтения [`stats.md`](../rest-api/resources/stats.md); после перезагрузки контроллера
  (часы выборки пошли назад) базовая выборка берётся заново. Отказом красится только
  ненулевой счётчик, чьё единственное здоровое значение — ноль; работа механизма
  (уступка фона, вытеснение `superseded`) — не отказ. Гейджи — без дельты.
- **Время контроллера**: возраст метки — по правилу `last_seen_ms`
  ([`state-contracts.md`](../rest-api/contracts/state-contracts.md)), а не от часов
  браузера.
- Шапка приложения показывает индикатор соединения ([`websocket.md`](websocket.md)) и
  значок роли на стэндбае ([`redundancy.md`](redundancy.md)).
