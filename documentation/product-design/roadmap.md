## Запланированные стадии

### R9 + I8 — настройки дисплея и страницы экрана

- `GET` / `PATCH /api/v1/settings/display` (merge-patch): включение, адрес I2C,
  поворот кратно 90°, таймаут хранителя (`0` — выключен), ограниченный список страниц
  для листания. Новая пара «команда настроек → событие изменения» в конце юнионов и
  свой слайс.
- Воркер дисплея получает листание страниц, поворот и хранитель экрана без рестарта;
  настройку он читает через read-порт, а событие только будит
  ([`../architecture/03-bus-and-backpressure.md`](../architecture/03-bus-and-backpressure.md)
  §Subscribers).
- Готово, когда настройки доходят до драйвера (или мок-границы) живьём, а стек воркера
  остаётся в бюджете. BDD — `SET-DISP-`, `DISP-`.

### I6 — кластер

Пересылка разрешённых групповых команд и recall сцен между контроллерами по MQTT с
подавлением петель. Проект, включая ресурс `/api/v1/cluster`, —
[`runtime-modules/cluster/README.md`](runtime-modules/cluster/README.md).

- Контракт: команда настроек и фильтра, событие изменения настроек, события приёма,
  пересылки и отказа; счётчики в `/stats`.
- До начала решить: пара отказоустойчивости делит `controller_id` и MQTT `client_id`,
  кластер должен различать узлы иначе.
- BDD — `CLU-`, сквозная проверка петель — `SYS-`.

### X2 — несколько адаптеров

Реестр, REST и шина уже адресуют адаптер, собран один
([`runtime-modules/README.md`](runtime-modules/README.md) §Один адаптер сегодня).
Целевая композиция:

- N транспортов DALI, у каждого свой PHY; распиновка — данными, парой TX/RX на адаптер;
- **один `DaliWorker` на физический адаптер**, маршрутизация по `target_adapter_id`,
  стабильные `BusId` / `adapter_id`;
- в одном экземпляре остаются шлюз API, хост шины, registry worker, проектор,
  трекер операций, оркестратор, транслятор сниффера, мост Home Assistant, HCL, поллер,
  дисплей, WebSocket, правила, отказоустойчивость, кластер и adapter proxy;
- статистика `dali` делится по адаптерам (`adapters[]`); раскладка слайсов уже держит
  слоты на восемь адаптеров;
- хостовый BDD — мок-транспорт на адаптер; на стенде — кадры и сниффер каждого
  адаптера.

Вместе с `X2` решаются границы «транспорт на адаптер» и `domain` ↔ `contracts`.

### I7 — adapter proxy

Проброс разрешённых групповых, сценовых и широковещательных команд между адаптерами
одного контроллера; после `X2`. Проект, включая ресурс `/api/v1/adapter-proxy`, —
[`runtime-modules/dali-proxy/README.md`](runtime-modules/dali-proxy/README.md).

- Контракт: команда настроек с правилами пересылки, событие изменения, события
  пересылки и отказа.
- BDD — `PROXY-`, петли — `SYS-`.

## Остатки построенных стадий

### R16-C — мы как control device

Что из роли control device не построено —
[`../reference/iec62386-conformance-gaps.md`](../reference/iec62386-conformance-gaps.md)
§8. Для `COMPARE` и чтения банка через DTR нужен отдельный отвечающий механизм: таблица
ответов их не выражает ([`runtime-modules/redundancy/README.md`](runtime-modules/redundancy/README.md)
§Ответ).

### R17 — отказоустойчивость

- Политики: список исключений (`exceptions`: хранение, учёт в применении, UI) и флаг
  дрейфа `policy_mismatch` на устройстве (сравнение при каждом чтении атрибутов).
- Порог захвата по умолчанию — открытый ISSUE-86 в [`known-issues.md`](known-issues.md).
- Стендовые подтверждения — в долге стенда.

### I10 — правила

- Носители глаголов, которые разбираются, но не исполняются: одиночный `hcl.hold`,
  `hcl.enable` / `hcl.disable` расписания, 303 `cancel_hold` / `catch_movement`, recall
  сцены на одиночную лампу.
- Носитель `hold_hcl=false`: признак «не считать коммит чужим» от команды через
  applied-факт, проектор и реестр до источника коммита.
- Приёмник текста `log()` и именованные счётчики `stat()`.
- Триггер `when mqtt "topic"` — зарезервирован грамматикой.
- Решить, должен ли `scene(N) recalled` срабатывать на чужой recall, увиденный
  сниффером.
- Экран: автодополнение имён из реестра; решить, что из UI-слоя (`RULE-050..059`)
  проверяется чёрным ящиком, а что — тестами web UI.

### Прочее

- `device_type_override` не участвует в capabilities: решить, снимает ли сужающее
  переопределение capability (первое вычитающее правило) или только сужает выбор групп
  чтения.
- TLS к брокеру MQTT (сейчас только `mqtt://`).

| Гейт «док против кода» для REST | ссылки проверяются, утверждения — нет | сверять маршруты и коды ошибок роутера с ресурсными документами — гейтить имена из кода, прозу оставить человеку |

| `executor/attributes.rs` | около тысячи строк рядом с уже вынесенными `common_102`, `dt6`, `dt8` | дорезать при следующей правке секций |
| Конструкторы `BusFrame` | берут конверт по значению и копируют его на стек публикующего потока до `Arc`; отсюда вложенные выражения в воркерах с тесным стеком | строить конверт сразу в памяти `Arc`, замерить кадры публикаторов до и после |
| `LightSetpoint::level` | `u8` без `Option`: «уровень не задан» выводится эвристикой по мощности и нулю, и её обязан знать каждый потребитель | `Option<u8>` с заменой эвристики в одном месте |
| Кадр `DiagnosticsSnapshot` | худший случай почти вплотную к потолку, новый счётчик приходится уводить в `/stats` | вынести медленный блок `redundancy` в свой канал или тип кадра, опустить потолок |
| Стеки `hcl-scheduler` и `mqtt_worker` | заняты больше чем на 80 % бюджета; глубокие пути — тик желаемого состояния и объявление свежей сессии MQTT | назвать кадры пробником `StackLowWater`, вынести глубокие, опустить бюджеты |
| Маска патча инстанса Part 103 | тест не видит бит, который потребляет конфигурация инстанса, но нет в `ALL_PATCH_BITS` | вести конфигурацию от одной таблицы битов |
| `KNOWN_DIVERGENCE` 0xA7 (модель против корпуса стенда) | причина неверна: модель умеет гир с несколькими типами, а расходятся драйверы, отвечающие на `QUERY NEXT DEVICE TYPE` не сразу за `QUERY DEVICE TYPE` | переписать причину; решить, воспроизводить ли нестрогость драйверов |
| Модель гира мягче стандарта | обход типов отменяют только кадры этому гиру; специальные команды не останавливают идентификацию (102 Table 93); пару send-twice рвёт только кадр этому гиру, а по 101 §9.3 — любой кадр между половинами | отменять обход и пару любым кадром сегмента, сбрасывать идентификацию на специальных командах, тесты |
| BDD-прогон последовательный | `max_concurrent_scenarios(1)`: временно-чувствительные проверки нестабильны в параллели | фичи несколькими процессами через `ONLY_FEATURES` |
| Коммишенинг без исполняемой проверки | нет теста успешной замены прибора, `409` при параллельной операции и занятом адресе, `verify_failed` смены адреса, сохранения HA `unique_id` | сценарии на скриптах обнаружения двух приборов и ответа другим адресом |

**Устаревшие обходы** — удалить, проверив посылку:

- атомарные `fetch_min` / `fetch_max` заменены парой load/store ради бэкенда Xtensa (минимум
  стека httpd, зонд аллокатора) — проверить, что на RISC-V они собираются;
- хостовые хранилища (атомарная запись файла, файловый `SliceStore`) удаляют цель перед
  `rename` ради LittleFS — на POSIX `rename` заменяет атомарно, а удаление эту атомарность
  ломает;
- `rust-toolchain.toml` закрепляет форк `esp` ради Xtensa — проверить прошивку и
  `just esp-check` на nightly с `rust-src`;
- чтение атрибутов перечитывает по сигнатурам «чистого, но неверного» ответа под опросом WB
  (удвоенный байт членства, нулевые возможности DT8, непредставимый extended fade), а ремонт
  программирования сцен и групп имеет бюджет 2 — посылка на текущей прошивке не подтверждена:
  поставить счётчик и снять обход, если он молчит;
- поля `Configuration` httpd выставляются присваиванием, а размер стека проверяет `assert`,
  из-за посылки, что литерал с `..Default::default()` теряет поля при `opt-level = "z"` —
  проверить её на текущем тулчейне, `assert` оставить;
- `build.rs` прошивки сканирует `src` на ручки `DALI2RUST_*` ради `rerun-if-env-changed` —
  проверить, не пересобирает ли cargo сам по `env-dep` в dep-info;
- раздел `phy_init` держится без радио — проверить загрузку без него.

**Отложено с триггером — приём DALI через RMT.** Фронты, защёлкнутые железом, убрали
бы на приёме класс «поздний тик портит захват»; передачу RMT в одиночку не закрывает
(обнаружение коллизии, слушающий лид, момент начала приёма остаются за прерыванием),
так что схема только гибридная. После `ADR-025` мотив слабее. Триггер: прошивка стенда
без провода (OTA или Mac в сети стенда) **и** независимый приёмник вместо снятой платы
`tools/dali-arbiter`. Ступени, каждая с откатом: параллельный RMT-сниффер и сверка с
битбангом → декодирование по RMT → передача через RMT со стартом из прерывания.

## Шаблон стадии

1. **Цель** — одно-два предложения.
2. **Зависимости** — предыдущие стадии, без ссылок вперёд.
3. **Контракты** — payload'ы (в конец юниона, с `budget`), DTO, слайсы и их версии.
4. **REST** — ресурсный документ.
5. **BDD** — префикс ID в [`bdd/ids-registry.md`](bdd/ids-registry.md), сценарии в
   `tests/dali2rust-bdd/features/<домен>/`.
6. **Порядок**: падающий BDD (`@wip`) → типы, контракты и хендлеры → исполнение в
   продакшн-композиции (не только в тестовой обвязке) → зелёный; предыдущие наборы не
   краснеют.
7. **Готово**: все сценарии зелёные, контрактные round-trip тесты, стадия в
   `status.md`, запись удалена отсюда.

## Отложенные хвосты

Мелкие открытые пункты, найденные в закрытых записях и при сверке документации с кодом.
Ни один не блокирует работу; порядок — по убыванию пользы.

- **Extended fade time ограничен `u16` мс.** Кодек множитель/база покрывает решётку IEC
  до 16 мин, но поле в реестре, DTO, запросе и событиях — `u16`, поэтому 2–16 мин
  недостижимы. Расширение — контрактная волна с бампом слайса физических устройств.
- **Сниффер не декодирует чужое программирование сцен (`SET SCENE`).** Нужен, чтобы
  помечать строку сцены «перечитать», а не показывать своё последнее значение.
- **Уровень неизвестен (MASK):** решить, что показывать в UI и Home Assistant, пока уровень
  не прочитан.
- **`sntp_sync` не входит в список логируемых целей,** поэтому строка о синхронизации
  часов не печатается.
- **Стенд не гейтит срабатывания task watchdog в serial-логе.**
- **Синхронные маршруты при выключенном адаптере** отвечают голым `409 conflict` без
  причины `adapter_disabled`, которую получают операции.
- **`/api/v1/controller` отдаёт заглушки** для `controller_id`, `network` и `cluster`.
- **BDD-гейты:** `verify_bdd_ids.sh` принимает теги стадий только до `R16`;
  `just bdd-stage STAGE` передаёт стадию позиционным аргументом, которого у cucumber нет.
- **Эмулятор gear:** зарезервированный блок коротких адресов (по умолчанию 0..=9) не
  покрывает все лампы инсталляции — расширить до выхода эмулятора на общий провод.
- **Банк 0:** строки 0–8 байта `0x1B` (конфигурация bus unit) отдаются как «unnamed row»,
  хотя таблица восстановлена в дайджесте 098bp (локально, вне git).
- **Панель Part 103 молчит на скан в окне фиксации NVM** после конфигурационной записи
  (фикстура стенда ждёт до 90 с) — проверить по IEC 62386-103, отклонение ли это.
- **Проверка дубликата короткого адреса:** два гира на одном адресе различает только поиск
  по random address внутри `INITIALISE` с этим адресом; ни один путь продукта его не
  запускает.
- **`pin_probe` на P4 не запускался:** список GPIO выведен из таблицы разъёма — прогнать на
  стенде только запросами на чтение.
