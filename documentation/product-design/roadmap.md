## Запланированные стадии

### R9 + I8 — настройки дисплея и страницы экрана

- `GET` / `PATCH /api/v1/settings/display` (merge-patch): включение, адрес I2C,
  поворот кратно 90°, таймаут хранителя (`0` — выключен), ограниченный список страниц
  для листания. Новая пара «команда настроек → событие изменения» в конце юнионов и
  свой слайс.
- Воркер дисплея получает листание страниц, поворот и хранитель экрана без рестарта;
  настройку он читает через read-порт, а событие только будит
  ([`../architecture/03-bus-and-backpressure.md`](../architecture/03-bus-and-backpressure.md)
  §Subscribers).
- Готово, когда настройки доходят до драйвера (или мок-границы) живьём, а стек воркера
  остаётся в бюджете. BDD — `SET-DISP-`, `DISP-`.

### I6 — кластер

Пересылка разрешённых групповых команд и recall сцен между контроллерами по MQTT с
подавлением петель. Проект, включая ресурс `/api/v1/cluster`, —
[`runtime-modules/cluster/README.md`](runtime-modules/cluster/README.md).

- Контракт: команда настроек и фильтра, событие изменения настроек, события приёма,
  пересылки и отказа; счётчики в `/stats`.
- До начала решить, как сессия кластера называет себя брокеру и на какой плате пары
  живёт: MQTT `client_id` моста Home Assistant равен `controller_id` и общий у пары.
- BDD — `CLU-`, сквозная проверка петель — `SYS-`.

### X2 — несколько адаптеров

Реестр, REST и шина уже адресуют адаптер, собран один
([`runtime-modules/README.md`](runtime-modules/README.md) §Один адаптер сегодня).
Целевая композиция:

- N транспортов DALI, у каждого свой PHY; распиновка — данными, парой TX/RX на адаптер;
- **один `DaliWorker` на физический адаптер**, маршрутизация по `target_adapter_id`,
  стабильные `BusId` / `adapter_id`;
- в одном экземпляре остаются шлюз API, хост шины, registry worker, проектор,
  трекер операций, оркестратор, транслятор сниффера, мост Home Assistant, HCL, поллер,
  дисплей, WebSocket, правила, отказоустойчивость, кластер и adapter proxy;
- статистика `dali` делится по адаптерам (`adapters[]`); раскладка слайсов уже держит
  слоты на восемь адаптеров;
- хостовый BDD — мок-транспорт на адаптер; на стенде — кадры и сниффер каждого
  адаптера.

Вместе с `X2` решаются границы «транспорт на адаптер» и `domain` ↔ `contracts`.

### I7 — adapter proxy

Проброс разрешённых групповых, сценовых и широковещательных команд между адаптерами
одного контроллера; после `X2`. Проект, включая ресурс `/api/v1/adapter-proxy`, —
[`runtime-modules/dali-proxy/README.md`](runtime-modules/dali-proxy/README.md).

- Контракт: команда настроек с правилами пересылки, событие изменения, события
  пересылки и отказа.
- BDD — `PROXY-`, петли — `SYS-`.

## Остатки построенных стадий

### R16-C — мы как control device

Что из роли control device не построено —
[`../reference/iec62386-conformance-gaps.md`](../reference/iec62386-conformance-gaps.md)
§8. Для `COMPARE` и чтения банка через DTR нужен отдельный отвечающий механизм: таблица
ответов их не выражает ([`runtime-modules/redundancy/README.md`](runtime-modules/redundancy/README.md)
§Ответ). Дизайн и пять решений, которые нужны до кода, —
[ADR-030](../architecture/decisions/ADR-030-controller-as-a-part-103-bus-unit.md).

### R17 — отказоустойчивость

- Политики: список исключений (`exceptions`: хранение, учёт в применении, UI) и флаг
  дрейфа `policy_mismatch` на устройстве (сравнение при каждом чтении атрибутов).
- Порог захвата по умолчанию — открытый ISSUE-86 в [`known-issues.md`](known-issues.md).
- Стендовые подтверждения — в долге стенда.

### Прочее

- `device_type_override` не участвует в capabilities: решить, снимает ли сужающее
  переопределение capability (первое вычитающее правило) или только сужает выбор групп
  чтения.
- TLS к брокеру MQTT (сейчас только `mqtt://`).

## Технический долг

| Что | Состояние | Шаг |
|---|---|---|
| HIL-ярус на эмулированных гирах | ярус есть ([`tools/hil`](../../tools/hil/README.md#virtual-gear)), но остальные тесты тулкита, двигающие свет, на эмулированные гиры не переведены | перевести target-state, группы, сцены, HCL, ввод, fanout, нагрузку, транзакции, банки, забывание и identify, расширяя список guard'а; оракул эмулятора — в форме `CameraOracle`; роль пира — в `peer_health`, `pair.hand_back` и `corpus` |
| Конструкторы `BusFrame` | берут конверт по значению и копируют его на стек публикующего потока до `Arc`; отсюда вложенные выражения в воркерах с тесным стеком | если перепись стеков покажет нехватку запаса у тесных воркеров — мономорфные строители кадра за `#[inline(never)]` ([07](../architecture/07-memory-and-cores.md) §Building large values) с замером кадров публикаторов до и после |
| Бюджет стека `mqtt_worker` ([`stack_budget.txt`](../../tools/hil/stack_budget.txt)) | его держит команда цвета Home Assistant с объектом RGB, но ни один тест тулкита её не шлёт, и перепись полного default этот путь не проходит | добавить в `test_ha_bridge` команду с объектом цвета, чтобы перепись полного default проходила путь бюджета |

**Устаревшие обходы** — удалить, проверив посылку:

- чтение атрибутов перечитывает по сигнатурам «чистого, но неверного» ответа под опросом WB
  (удвоенный байт членства, нулевые возможности DT8, непредставимый extended fade), а ремонт
  программирования сцен и групп имеет бюджет 2 — посылка на текущей прошивке не подтверждена:
  следить за счётчиками исправлений, когда перечитывание дало другой ответ, и потраченных
  ремонтов (блок `dali` в `/api/v1/stats`, строки `watched` сводки валидности HIL) и снять
  обход, когда они остаются нулевыми;
- раздел `phy_init` убран из таблицы разделов: ESP-IDF не собирает для ESP32-P4 кода, который
  его ищет. Таблица доходит до платы только проводной прошивкой — первая такая прошивка и есть
  проверка загрузки без раздела.

**Отложено с триггером — приём DALI через RMT.** Фронты, защёлкнутые железом, убрали
бы на приёме класс «поздний тик портит захват»; передачу RMT в одиночку не закрывает
(обнаружение коллизии, слушающий лид, момент начала приёма остаются за прерыванием),
так что схема только гибридная. После `ADR-025` мотив слабее. Триггер: прошивка стенда
без провода (OTA или Mac в сети стенда) **и** независимый приёмник вместо снятой платы
`tools/dali-arbiter`. Ступени, каждая с откатом: параллельный RMT-сниффер и сверка с
битбангом → декодирование по RMT → передача через RMT со стартом из прерывания.

## Шаблон стадии

1. **Цель** — одно-два предложения.
2. **Зависимости** — предыдущие стадии, без ссылок вперёд.
3. **Контракты** — payload'ы (в конец юниона, с `budget`), DTO, слайсы и их версии.
4. **REST** — ресурсный документ.
5. **BDD** — префикс ID в [`bdd/ids-registry.md`](bdd/ids-registry.md), сценарии в
   `tests/dali2rust-bdd/features/<домен>/`.
6. **Порядок**: падающий BDD (`@wip`) → типы, контракты и хендлеры → исполнение в
   продакшн-композиции (не только в тестовой обвязке) → зелёный; предыдущие наборы не
   краснеют.
7. **Готово**: все сценарии зелёные, контрактные round-trip тесты, стадия в
   `status.md`, запись удалена отсюда.

## Отложенные хвосты

Мелкие открытые пункты, найденные в закрытых записях и при сверке документации с кодом.
Ни один не блокирует работу; порядок — по убыванию пользы.

- **Extended fade time ограничен `u16` мс.** Кодек множитель/база покрывает решётку IEC
  до 16 мин, но поле в реестре, DTO, запросе и событиях — `u16`, поэтому 2–16 мин
  недостижимы. Расширение — контрактная волна с бампом слайса физических устройств.
- **Стенд не гейтит срабатывания task watchdog в serial-логе.**
- **Проверка дубликата короткого адреса:** два гира на одном адресе различает только поиск
  по random address внутри `INITIALISE` с этим адресом; ни один путь продукта его не
  запускает.
- **`pin_probe` на P4 не запускался:** список GPIO выведен из таблицы разъёма — прогнать на
  стенде только запросами на чтение.
