# Правила: язык v1 — полный словарь и грамматика

Это канон того, **что правило умеет**. Runtime-поведение движка — в
[`README.md`](README.md), REST-контракт — в
[`../../rest-api/resources/rules.md`](../../rest-api/resources/rules.md), решения —
в [`ADR-016`](../../../architecture/decisions/ADR-016-input-devices-and-rule-engine.md).
Глагол, который разбирается, но пока не имеет носителя на шине, помечен ниже
«не исполняется»: движок считает его в диагностике и ничего не делает.

Грамматика ниже — это `LANG_RULES_V1 = 1`, крейт `dali2rust-rules-lang`. Что канон —
исходный текст с комментариями и что язык заменяем без правки движка —
[`README.md`](README.md) и `ADR-016`.

**Расширяемость словаря:** один глагол = одна декларация в реестре видов
(`TriggerKind` / `ConditionKind` / `ValueKind` / `ActionKind`). Тест тотальности держит
четвёрку «парсер + исполнитель + учёт лимитов + строка в этом документе» в сборе, а
грамматика **append-only**: исходник, разобранный вчера, обязан разбираться и завтра.

## Форма документа

```
# комментарий до конца строки

def "имя блока" {
  <действие>
  …
}

rule "имя правила" [enabled false] [cooldown 500ms] [hold_hcl true] {
  when  <триггер>                  # 1..4 строк when = ИЛИ между ними
  if    <условие> [and <условие>]  # 0..4, только AND
  do    <действие>                 # 1..8 строк
        <действие>
}
```

- **Идентичность правила — имя** (`ADR-016`): уникальность требует парсер, по имени
  ключуются ручки `PATCH`/`run`. Пер-правило runtime-полей (`fire_count`,
  `last_outcome`) в проекции **нет** (открытый `ISSUE-100`).
- **Несколько `when` — это ИЛИ**, и это единственная форма дизъюнкции в языке. Между
  условиями `or` нет: два условия через ИЛИ — это два правила.
- Приоритет при совпадении триггера у нескольких правил — по возрастанию имени
  (лексикографически), детерминированно.

Модификаторы правила:

| Модификатор | По умолчанию | Смысл |
|---|---|---|
| `enabled true\|false` | `true` | Начальное значение бита в манифесте слайса; дальше им владеет `PATCH /rules/{name}` |
| `cooldown <длит>` | `0`, если хотя бы один триггер — событие входа, иначе `200ms` | Повторная активация раньше — `cooldown_suppressed` |
| `hold_hcl true` | `true` | Световое действие ставит HCL-override для цели; `false` отвергается компилятором (§4.1) |

## Лексика

| Элемент | Форма |
|---|---|
| Комментарий | `# …` до конца строки |
| Имя-строка | `"…"`, UTF-8, ≤ 48 Б |
| Длительность | `500ms`, `0.7s`, `5m`, `2h` |
| Время суток | `HH:MM` (локальное) |
| Уровень | `0..254` (DAPC) |
| Цветовая температура | кельвины, напр. `2700` |
| Целое | со знаком, для относительных шагов `+8` / `-8` |

## 1. Триггеры (`when`) — 1..4 на правило

### 1.1 Вход IEC 62386-103 — кнопки (part 301)

```
when input(dev=3, inst=0) is short_press
when input("панель-прихожая", inst=1) is long_press_repeat
when input(group=2, type=button) is press        # instance-group адресация
when input(adapter=1, dev=3, inst=0) is press    # явный скоуп, см. §5
```

| Событие | Код (10 бит) | Когда приходит |
|---|---|---|
| `release` | `0x000` | палец убрали |
| `press` | `0x001` | палец коснулся |
| `short_press` | `0x002` | короткое нажатие завершилось |
| `double_press` | `0x005` | двойное нажатие |
| `long_press_start` | `0x009` | удержание распознано (через T_short) |
| `long_press_repeat` | `0x00B` | периодический повтор, пока держат |
| `long_press_stop` | `0x00C` | удержание закончилось |
| `button_free` | `0x00E` | кнопка освободилась после залипания |
| `button_stuck` | `0x00F` | кнопка залипла |

Три свойства 301, которые видны в правилах и в UI:

- **`double_press` стоит задержки.** Заводская конфигурация (фильтр `0xF4`,
  `tDouble = 0`) даёт `short_press` **на отпускании без задержки**; включение двойного
  нажатия на этом инстансе задерживает **каждый одиночный клик** на T_double
  (200..2000 мс). Это продуктовый компромисс, а не тюнинг: UI обязан предупредить при
  привязке `double_press`.
- **`long_press_repeat` легально теряется** под нагрузкой шины (103 §9.4.7 гарантирует
  доставку только последнего события). Поэтому диммирование удержанием — это
  `.dim_hold(rate)`, считающий по времени, а не `.dim(+8)` на каждое событие.
- **Подмены**: `double_press` замещает второй `press`, `long_press_stop` замещает
  завершающий `release`. Автомат, считающий фронты по именам событий, разъедется;
  признак «нажата/отпущена» — бит 0 кода события.

Какие события устройство вообще присылает — решает его event filter. UI показывает
фактически включённые (`enabled_events` инстанса), а не весь список.

### 1.2 Вход — датчики присутствия (part 303)

```
when input(dev=5, inst=0) becomes occupied
when input(dev=5, inst=0) becomes vacant
when input(dev=5, inst=0) is movement
when input(dev=5, inst=0) is no_movement
```

- `becomes occupied` / `becomes vacant` — **только переходы**. Повторное «всё ещё
  занято» (report-таймер датчика) правило не будит: это отдельный код события, и
  наивный предикат «бит occupied взведён» перезапускал бы правило каждые T_report.
- `movement` / `no_movement` приходят только если включён соответствующий бит фильтра;
  стандарт сам предупреждает, что movement-события способны залить шину.
- **Момента «человек ушёл» у движенческого датчика не существует.** `vacant` у него —
  это истечение hold-таймера, который **стоит, пока движение продолжается, и стартует,
  когда движение кончилось**. Presence-класс датчика шлёт `vacant` сразу; класс виден
  в реестре (бит 3 кода события) и в UI. Реальная выдержка = T_hold датчика + задержки
  правила, и UI показывает эту сумму.

### 1.3 Вход — датчик света (part 304) и абсолютный вход (part 302)

```
when input(dev=6, inst=0).light crosses above 400
when input(dev=6, inst=0).light crosses below 150
when input(dev=7, inst=0).position changes
```

Значение 304 — **относительное и безразмерное**; люксы, если они нужны, получаются из
нашей пер-девайсной калибровки, а пороги в правиле задаются в сырых единицах датчика.
MASK от датчика означает «прогрев **или** отказ» и никогда не считается числом:
`crosses` на MASK не срабатывает.

### 1.4 Вход — generic и служебные события устройства

```
when input(dev=3, inst=2) is any_event
when input(dev=3, inst=2) is event(data=1)     # сырые 10 бит
when input device(dev=3) power cycled          # питание панели передёрнули
when input device(dev=3) manual config changed # part 333: крутили локально
```

`power cycled` — триггер переутверждения индикации панели
([модуль input devices](../input-devices/README.md) §Индикация).

**`manual config changed` срабатывает на ЧТЕНИИ, а не на повороте ручки.** Флаг
Part 333 приезжает в `Dali103InstanceConfiguredEvent`, то есть тогда, когда
контроллер сам прочитал инстанс; незапрошенного уведомления провод не несёт.
Первое чтение инстанса только заводит базу — «изменилось» о никогда не читанном
инстансе сказать нечего. Триггер адресует УСТРОЙСТВО, а флаг живёт на инстансе,
так что несколько инстансов одной панели, сдвинувшихся вместе, зажгут правило
несколько раз.

### 1.5 Время

```
when at 07:30 on mon,tue,wed,thu,fri
when at sunrise-15m
when at sunset+30m
when every 15m
```

Астрономия — общая с HCL, и оговорка та же: **без привязанных часов правило времени не
срабатывает** и считается в `ticks_time_unsynced`. Минимальный период `every` — 1 s.

### 1.6 Состояние

```
when lamp("коридор") turns on
when lamp("коридор") turns off
when lamp("коридор").level crosses above 100
when group("кухня") becomes any_on
when group("кухня") becomes all_off
when scene(3) recalled
when device(3) goes offline
when device(3) comes online
when hcl override starts for group("кухня")
when hcl override clears for group("кухня")
```

Источник — `RuntimeStateChangedEvent`; `scene(N) recalled` — recall, исполненный этим
контроллером (`DaliSceneRecalledEvent`): чужой recall, увиденный сниффером, этот
триггер не будит. Триггер срабатывает на **переход**, а не на факт.

Три перехода из этого списка выводятся не из события, а из снимка, и вот почему:

| Переход | Откуда | Задержка |
|---|---|---|
| `group(...) becomes ...` | из того же `RuntimeStateChangedEvent`: реестр публикует его ПОСЛЕ коммита, так что агрегат в снимке — уже тот, о котором событие | событийная |
| `device(N) goes offline/comes online` | тик: «пропал» — это истечение окна с последнего ответа, кадра об этом не бывает | ≤ 1 с |
| `hcl override starts/clears` | тик: старт поднимает ЧУЖОЙ воркер (планировщик HCL), реагируя на то же событие на своём потоке, — читать его реестр на приходе означало бы гонку, а снятие (`hcl.resume`, REST, полночь) не несёт события вовсе | ≤ 1 с |

### 1.7 Таймеры, система, внешние

```
when timer("прихожая") fires
when controller starts             # один раз после boot
when controller becomes active     # переход passive → active (стэндбай)
when rule("ночной режим") fails
when http trigger                  # POST /api/v1/rules/{name}/run
```

`controller starts` и `controller becomes active` — один и тот же способ восстановить
режимы; на активном одиночном контроллере boot даёт оба. Захват роли standby'ем даёт
их тоже (`ADR-016`: захват ≡ загрузка), и роль берётся из
`RedundancyTransitionEvent`, а не перечитывается из реестра: арбитр публикует событие
после того, как роль сдвинул, а у входа, читающего реестр обратно, второй попытки нет.

`rule("X") fails` срабатывает, когда активация X не смогла сделать то, что написано:
исполнитель взялся за эффект и не смог его выполнить, либо движок активацию урезал
(`partial`). Эффект, пропущенный ПО ЗАМЫСЛУ — `.dim()` на погашенной лампе — это не
отказ, и сухой прогон не сообщает ни о чём. Глубина ровно одна: активация, до которой
довёл отказ, о своём отказе не сообщает — иначе `rule "X" { when rule("X") fails … }`
уходит в рекурсию до конца стека воркера.

Зарезервировано грамматикой, **в v1 не исполняется** ([`../../roadmap.md`](../../roadmap.md) §I10):
`when mqtt "topic" [is "payload"]`.

## 2. Условия (`if`) — 0..4, только AND

### 2.1 Время и день
```
time in 07:00 .. 23:00
time in sunset-30m .. sunrise+15m     # интервал через полночь допустим
day in mon..fri
day in sat,sun
sun is up
sun is down
```

### 2.2 Свет
```
lamp("X") is on
lamp("X") is off
lamp("X").level >= 100
lamp("X").cct <= 3000
group("кухня") any_on
group("кухня") all_off
```
Операторы сравнения: `==`, `!=`, `>=`, `<=`, `>`, `<`.

### 2.3 Входные устройства
```
input(dev=5, inst=0) is occupied
input(dev=5, inst=0) is vacant
input(dev=6, inst=0).light above 300
input(dev=6, inst=0).light below 150
```
Читается **текущее состояние из реестра** (последнее наблюдённое), не с провода.

### 2.4 Автоматика, устройства, движок
```
hcl is enabled for group("кухня")
hcl is overridden for group("кухня")
device(3) is online
rule("X") is enabled
last_fired("X") older than 10m
timer("X") is running
controller is active
var("режим") == "ночь"
var("счётчик") >= 3
```

`controller is active` нужен несветовым действиям на пассивном узле: световые команды
и так гасятся TX-гейтом, а `mqtt.publish` — нет.

Отсутствие — тоже ответ: несуществующая переменная или переменная другого типа ни с чем
не равна (истинно только `!=`); правило, которое ни разу не срабатывало, для
`last_fired(…) older than` бесконечно старо; устройство без строки в реестре — не в
сети; цель без строки HCL — ни под расписанием, ни приостановлена. Лампа или группа,
которых нет в read-модели, делают условие невычислимым (`partial`).

## 3. Читаемые значения

| Выражение | Источник |
|---|---|
| `lamp("X").level`, `.cct`, `.is_on`, `.last_level` | Read-модель реестра |
| `group("X").any_on`, `.all_off`, `.member_count` | Read-модель реестра |
| `input(d,i).occupied`, `.light`, `.position`, `.last_event_age` | Реестр входных устройств |
| `time.now`, `.hour`, `.minute`, `.weekday` | Локальное время контроллера |
| `sun.rise`, `.set`, `.is_up` | Астрономия (общая с HCL) |
| `var("X")` | Переменные движка (volatile) |
| `event.value` | Значение события активации (10 бит / типизированное) |
| `event.device`, `event.instance` | Источник события активации |
| `event.option` | `instanceGroup0` инстанса-источника — номер опции для радиокнопок |

Контекст события — это то, что делает одно правило заменой восьми:

```
rule "слайдер яркости" {
  when input(dev=7, inst=0).position changes
  do   group("кухня").level(event.value)
}

rule "сценные кнопки панели" {
  when input(group=4, type=button) is short_press
  do   scene(event.option).recall(group("зал"))
       panel_select(group=4, selected=event.option)
}
```

Выражения v1: литерал | значение | `значение ± литерал`. Полная арифметика сознательно
не открывается — добавляется append-only, когда появится сценарий.

## 4. Действия (`do`) — 1..8 строк; после разворота блоков и `repeat` ≤ 32

Цель светового действия — `lamp("имя"|id)`, `group("имя"|id)` или `broadcast`.
Все чтения — из read-модели реестра, **никогда с провода** (`ADR-016`).

### 4.1 Свет

| Операция | Смысл |
|---|---|
| `.on(level?)` | Включить; без `level` — last-active level |
| `.off()` | Выключить |
| `.toggle(level?)` | По текущему состоянию из read-модели |
| `.level(N)` | Абсолютный DAPC `0..254` (принимает `event.value`) |
| `.level(+N)` / `.level(-N)` | Относительный шаг с насыщением |
| `.dim(+N)` / `.dim(-N)` | То же, но **не включает выключенную лампу** |
| `.dim_hold(+N)` / `.dim_hold(-N)` | Шаг за секунду удержания: движок считает по времени, а не по числу `long_press_repeat` |
| `.cct(K)` / `.cct(+K)` / `.cct(-K)` | Цветовая температура |
| `.xy(x, y)` | Координаты CIE 1931 |
| `.rgb(r, g, b)` | RGB (sRGB, `ADR-022`) |
| `.last_active()` | `GO TO LAST ACTIVE LEVEL` (уставка «включить» без уровня) |
| `.stop_fade()` | Остановить текущий переход на лампе, группе или broadcast — [`DaliStopFadeCommand`](../../bus-contracts/semantic-dali-commands.md) |

Общий модификатор один: `hold_hcl`, и у него разрешено только значение
`true` — то есть умолчание. `hold_hcl=false` **отвергается компилятором**: носителя
признака «коммит мой, не считать его чужим» на пути к источнику коммита пока нет — в
отличие от `fade=`, это не невозможно, а не сделано
([`../../roadmap.md`](../../roadmap.md) §I10).

`fade=<длит>` **отвергается компилятором**. Покомандного фейда в DALI нет: 102 §9.5
берёт длительность любого перехода из переменных, лежащих **в самом гире**
(`fadeTime`, а при нуле — `extendedFadeTime` / быстрый фейд Part 207), а программный
рамп из кадров `DAPC` — это ровно тот неограниченный всплеск, который запрещает
`ADR-007`. Длительность задаётся один раз на гир через
`POST /api/v1/adapters/{id}/physical-devices/{sa}/write-attributes`
(`common_102.fade_time_ms`), и её используют все команды к этому гиру — из правил, из
Home Assistant, из HCL и из сцен.

Два правила из инвариантов кода, а не из вкуса:

- **Цветовое действие не включает лампу.** `.cct()` / `.xy()` / `.rgb()` ставят цвет и
  не трогают питание.
- **`.dim()` и `.dim_hold()` на выключенной лампе — no-op**, иначе удержание «вниз» на
  погашенном свете его зажигает.

### 4.2 Сцены

| Операция | Смысл |
|---|---|
| `scene(N).recall(target?)` | `GO TO SCENE` — один кадр, яркость и цвет атомарно; цель — группа или broadcast (на одиночную лампу не исполняется) |
| `scene(N).apply()` | Оркестрованное применение (apply-orchestrator) |
| `scene.cycle(1, 3, 7)` | Следующая сцена из списка; позиция — volatile-состояние правила |

### 4.3 HCL

| Операция | Смысл |
|---|---|
| `hcl.resume(target)` | Снять override — вернуть цель под расписание |
| `hcl.hold(target)` | Поставить override, свет не трогая — **не исполняется**; световое действие с `hold_hcl` и так приостанавливает расписание |
| `hcl.enable("расписание")` / `hcl.disable("расписание")` | Расписание целиком — **не исполняется** |

### 4.4 Входные устройства и индикация (part 332)

| Операция | Смысл |
|---|---|
| `input(d,i).feedback.on()` / `.off()` | `ACTIVATE` / `STOP FEEDBACK` на один инстанс |
| `panel_select(group=G, selected=N)` | Радиокнопки индикации: `SELECT FEEDBACK(G)` с выбранной опцией `N` — [модуль input devices](../input-devices/README.md) §Индикация |
| `input(d,i).cancel_hold()` | 303: принудительный переход в vacant, не дожидаясь T_hold — **не исполняется** |
| `input(d,i).catch_movement()` | 303: одноразовое movement-уведомление при выключенном фильтре — **не исполняется** |

### 4.5 Время, задержки, последовательности

| Операция | Смысл |
|---|---|
| `wait <длит>` | Пауза внутри цепочки — **континуация**, не sleep |
| `after <длит> do { … }` | Отложенный блок (глубина 1) |
| `timer("X").start(<длит>)` / `.restart(<длит>)` / `.cancel()` | Именованный таймер → триггер `timer("X") fires` |

Континуации ограничены (`MAX_PENDING_CONTINUATIONS = 32`); переполнение считается в
`continuations_dropped`, а не теряется молча.

### 4.6 Структура

| Операция | Смысл |
|---|---|
| `call("блок")` | Вызов `def`-блока; глубина вызова ≤ 2, рекурсия невозможна конструктивно |
| `repeat N { … }` | Повтор блока действий; `N` — литерал ≤ 8, вложенный `repeat` запрещён |
| `if <условие> { … } else { … }` | Ветвление в действиях, глубина 1 |

Всё это **разворачивается** в плоский список шагов: компилятор проверяет лимиты
(`MAX_ACTIONS_EXPANDED = 32`) по развёрнутому виду, а движок разворачивает граф при
активации (`call` встраивается, `repeat` умножается) и остаётся плоским интерпретатором
без стека вызовов. Ветвь `if … { } else { }` остаётся узлом и выбирается, когда
исполнение до неё дошло: после `wait` условие читает мир своего момента, а не момента
триггера.

```
def "ночной контур" {
  scene(13).recall(group("ночь"))
  timer("ночь-выкл").restart(3m)
}
```

Удаление блока, на который ссылаются правила, парсер отклоняет — с перечислением
ссылающихся правил в тексте ошибки.

### 4.7 Переменные, правила, внешние эффекты

| Операция | Смысл |
|---|---|
| `var("режим").set("ночь")` | Строка ≤ 16 Б или число |
| `var("счётчик").add(1)` | Целочисленная арифметика с насыщением |
| `rule("X").enable()` / `.disable()` | Включить/выключить другое правило — только волатильный бит движка: манифест и `enabled` в REST не меняются, а любая перезагрузка набора (сохранение документа, `PATCH` бита, загрузка, перечитывание слайсов) возвращает биты документа; `.disable()` отменяет ожидающие продолжения правила |
| `mqtt.publish("<topic>", "<payload>", retain?)` | topic ≤ 48 Б, payload ≤ 48 Б (лимит `MAX_BUS_WIRE_BYTES`) |
| `log("текст")` | Считается в диагностике; сам текст пока никуда не уходит |
| `stat("имя").count()` | Считается одним общим счётчиком в диагностике; имя не различается |

Переменные и таймеры **волатильны** (§6); режимы после загрузки восстанавливает правило
на `when controller starts`.

`mqtt.publish` идёт командой на шину и исполняется мостом MQTT — единственным
владельцем брокерского клиента, со своим ограничителем
([`../mqtt-home-assistant/README.md`](../mqtt-home-assistant/README.md)).

## 5. Скоуп ссылок: мульти-адаптер и кластер

Каждая сущностная ссылка в модели — `(adapter_id, id)`, никогда голый id
(`ADR-016`). Автор текста скоуп обычно не пишет: `NameResolver` резолвит имя против
реестра, а имена уникальны. Явный квалификатор есть в грамматике v1 и валидируется:

```
when input(adapter=1, dev=3, inst=0) is short_press
do   lamp("коридор", adapter=0).toggle()
```

На одноадаптерной сборке `adapter=N`, где `N` — не первичный адаптер, даёт ошибку
разбора с координатами. Когда появится adapter-proxy (`I7`), чужой сегмент станет
локальным `adapter_id`, и правило «кнопка там — свет здесь» будет обычным правилом с
этим квалификатором: ни одного нового понятия в языке.

## 6. Что сознательно **не** включено

| Не делаем | Почему |
|---|---|
| Чтение с провода (`query`) | Чтение DT8 по проводу занимает секунды — на порядок больше всего бюджета «палец → свет» |
| `foreach` по лампам группы | Группа/сцена/broadcast **и есть** цикл, исполняемый одним кадром провода; поштучный обход — это бёрст на шину (`ADR-007`) |
| Сырой DALI из правила | Диагностический путь не смешивается с продуктовым; словарь расширяется типизированным глаголом за одну декларацию |
| Произвольный HTTP наружу | Блокирующий сетевой вызов в воркере, который обязан отвечать на следующее нажатие |
| Персистентные переменные | Переписывание флеша на каждое присваивание |
| Вложенные `if` глубже 1, `or` между условиями | Выражается вторым правилом или `def`-блоком |
| Полная арифметика и работа со строками | Сценариям не нужна; добавляется append-only, если появится случай |
| Функции с параметрами | `def`-блоки без параметров закрывают переиспользование; параметризация — кандидат `v1.1` |

---

Имена и значения переменных в примерах укладываются в лимиты раздела «Лексика»
(имя ≤ 48 Б, текст переменной ≤ 16 Б; кириллица — 2 Б на символ); компилятор
закрепляет это тестом на самих примерах.

## 7. Разобранные примеры

**Одна кнопка на всё** — короткое нажатие переключает, удержание диммирует, двойное
включает на полную:

```
rule "коридор: вкл/выкл" {
  when input(dev=3, inst=0) is short_press
  do   lamp("коридор").toggle()
}

rule "коридор: диммирование" {
  when input(dev=3, inst=0) is long_press_repeat
  do   lamp("коридор").dim_hold(+60)      # 60 шагов в секунду удержания
}

rule "коридор: полный свет" {
  when input(dev=3, inst=0) is double_press
  do   lamp("коридор").on(level=254)
}
```

**Ночной свет по датчику или кнопке, с предупреждением перед выключением:**

```
def "ночной контур" {
  scene(13).recall(group("ночь"))         # 30/254 и 2200 K одним кадром
  timer("ночь-выкл").cancel()
}

rule "ночь: вход" {
  when input(dev=5, inst=0) becomes occupied
  when input(dev=3, inst=0) is short_press
  if   time in 23:00 .. sunrise
  do   call("ночной контур")
}

rule "ночь: погашение" {
  when input(dev=5, inst=0) becomes vacant
  if   time in 23:00 .. sunrise
  do   group("ночь").level(10)   # притухли: «сейчас выключусь»
       timer("ночь-выкл").start(30s)
}

rule "ночь: выключение" {
  when timer("ночь-выкл") fires
  do   group("ночь").off()
       hcl.resume(group("ночь"))
}
```

**Сценная панель с индикацией** (радиокнопки, `instanceGroup1 = 4` у набора):

```
rule "зал: сцены с панели" {
  when input(group=4, type=button) is short_press
  do   scene(event.option).recall(group("зал"))
       panel_select(group=4, selected=event.option)
}

rule "зал: вернуть индикацию" {
  when input device(dev=3) power cycled
  do   panel_select(group=4, selected=var("зал-сцена"))
}
```

**«Ушёл»** — гасим всё, через 5 минут отдаём управление расписанию:

```
rule "ушёл" {
  when input(dev=3, inst=2) is long_press_start
  do   broadcast.off()
       var("режим").set("нет дома")
       mqtt.publish("dali2rust/mode", "away", retain=true)
       after 5m do { hcl.resume(broadcast) }
}
```

**Восстановление режима после перезагрузки:**

```
rule "boot: режим по умолчанию" {
  when controller starts
  when controller becomes active
  do   var("режим").set("обычный")
       panel_select(group=4, selected=1)
}
```
