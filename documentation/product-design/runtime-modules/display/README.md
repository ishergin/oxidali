# Модуль display

Сводный экран на встроенном OLED 128×64: семь строк по 21 знакоместу, которые отвечают
оператору у щита «жив ли контроллер, что с шиной и что только что произошло».

Границы: настройки экрана, листание страниц, поворот и хранитель — не реализованы
([`../../roadmap.md`](../../roadmap.md) §R9); что роль контроллера значит —
[`../redundancy/README.md`](../redundancy/README.md). Код — `dali2rust-display-runtime`
(воркер, раскладка экрана, драйвер SSD1306 по I2C); источник данных собирает композиция.

## Что показывает экран

| Строка | Содержание | Тревога (инверсия строки) |
|---|---|---|
| Адрес | IP-адрес и время работы; перед временем — буква роли `A` / `S`, если включена отказоустойчивость | стэндбай; нет адреса — `NO IP  LINK DOWN` |
| Устройства | `GEAR` отвечающие/известные гиры (с числом неисправных) и `IN` присутствующие/известные устройства ввода | есть неисправный гир |
| Шина | вердикт health-probe (`OK`, `LAMP FAIL`, `LAMP FAIL 2+`, `NO ANSWER`), кадры в минуту и из них чужие, справа — гистограмма загрузки провода за последнюю минуту | вердикт — тревога; адаптер выключен — `BUS  DISABLED` (гистограмма остаётся: провод несёт чужие кадры) |
| HCL | Tc последней применённой уставки HCL или `IDLE`, число активных override | — ; без гражданского времени — `HCL  STOPPED NO TIME` |
| Сервисы | поллер (`OFF` или период и `OK` / `ER` / `NA`), мост MQTT (`MQTT+` / `MQTT-`), число клиентов WebSocket | запись конфигурации на флеш не удалась — `NO SAVE` |
| Вход | последнее событие устройства ввода: адрес и инстанс, событие; `SCH0` — схема без идентичности устройства | — |
| Живая | идущая операция с прогресс-баром — или последнее действие: цель, что сделано, источник, возраст | действие провалилось |

- Буква роли стоит перед временем работы, потому что при нехватке места строка
  обрезает хвост, а роль больше нигде на экране не видна. Без отказоустойчивости
  буквы нет: вечная `A` на одиночном контроллере — подпись, которую никто не читает.
- Гистограмма — шестнадцать столбцов по одному пикселю, по отсчёту раз в несколько
  секунд из общего счётчика загрузки провода; ненулевая загрузка рисуется хотя бы одним
  пикселем.
- Возраст показывается относительно, а не временем суток: так он верен и до SNTP.

## Входы

- **События** — десять видов, все редкие по построению: адрес получен, итог
  health-probe, событие входа, статус операции, прогресс скана, applied-факт и отказ
  target-state, recall сцены, наблюдение сниффера, изменение расписания HCL — факты, а
  не числа и не настройки
  ([`../../../architecture/03-bus-and-backpressure.md`](../../../architecture/03-bus-and-backpressure.md)
  §Subscribers).
- **Снимок** `DisplaySource` — счётчики и настройки из реестра под одной блокировкой
  плюс атомарные счётчики провода, поллера, мостов и персиста; почему не виды записей —
  [`../../../architecture/07-memory-and-cores.md`](../../../architecture/07-memory-and-cores.md)
  §Workers read narrow views.

## Поведение

- Отдельный воркер с небольшим инбоксом событий; ждёт на инбоксе, не опрашивает.
  Потерянное событие стоит одной устаревшей секунды на экране.
- Выборка источника и перерисовка идут не чаще раза в секунду при любом потоке
  событий: события только копятся, а выборка берёт блокировку чтения реестра.
- Строки строятся по одной и перерисовываются, только если изменились; раскладка
  проверяется хостовыми тестами — строка, шире экрана, молча обрезалась бы драйвером.
- Ошибки драйвера и раскладки не мутируют реестр и ничего не публикуют; на хосте и в
  BDD — пустой бэкенд.

## Тесты

Раскладка и строки — unit-тесты `screen.rs` и `tests/summary_rows.rs` в
`dali2rust-display-runtime`: от события продюсера до строки. Загрузку и совместную
работу с `DaliWorker` проверяет системный BDD.
