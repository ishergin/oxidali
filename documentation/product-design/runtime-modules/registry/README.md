# Модуль registry

Единственный владелец внутреннего представления: адаптеры, виртуальные лампы,
физические устройства, устройства ввода, группы, сцены, расписания HCL, настройки и
runtime-состояние. Всё остальное читает его через read-порты и меняет только командами
шины.

Границы: как устроены блокировка, слияние runtime, слайс-стор, версии и гидрация —
[`../../../architecture/06-registry-and-persistence.md`](../../../architecture/06-registry-and-persistence.md);
контракт чтения — [`read-port.md`](read-port.md); состав слайсов —
[`../../bus-contracts/snapshots.md`](../../bus-contracts/snapshots.md). Код —
`dali2rust-registry-runtime`.

## Входы и выходы

- **Единая воронка** одного потока-писателя: команды реестра
  (`REGISTRY_WORKER_HANDLED_COMMANDS`, [`../../bus-contracts/commands.md`](../../bus-contracts/commands.md))
  и события-доказательства (`REGISTRY_EVENTS_HANDLED_EVENTS`) приходят в один инбокс
  в порядке прихода.
- **Публикует** события изменений после коммита, `RuntimeStateChangedEvent` после
  runtime-коммита, подтверждения записям, сигнал операции для чанковых записей
  (через `publish_required`) и `RegistrySliceReloadedEvent` после перечитки слайсов.
- **Предоставляет** `RegistryReadPort` и узкие read-порты, мосты `*HttpState` для
  HTTP и счётчики применения (apply-watch) для хендлеров настроек и моста Home Assistant.

## Чем владеет и откуда оно меняется

| Состояние | Меняется из |
|---|---|
| Конфигурация (имена, привязки, метаданные, override, desired-матрицы, расписания, настройки, политики) | команд реестра; чанковые записи — только закрывающей скобкой серии |
| Доказательства устройств (атрибуты, набор типов, capability, банки памяти) | событий: прогресс скана, итог сверки, чанки чтения атрибутов, подтверждённая запись атрибутов, завершённое чтение банка |
| Applied членство и applied-строки сцен | readback'и программирования и чтения (`QUERY GROUPS`, уровни сцен, цвет сцен) — никогда из desired; чужая запись сцены, увиденная сниффером, делает уровень непрочитанным, а чужое удаление из сцены там, где адресат известен наверняка, ставит `MASK` с источником `write_confirmed` |
| Идентичность устройства при коммиссионинге | итогов смены адреса и замены: запись переносится вместе с привязкой лампы только на чистом успехе |
| Записи устройств ввода и их инстансов | прогресса скана Part 103, итогов конфигурации, событий входа и служебных событий |
| Runtime ламп | только `RegistryRuntimeUpdateCommand` и `RegistryLevelTransitionCommand` от проектора |
| Активная сцена, «группой командовали» | recall сцены и групповых applied-фактов и наблюдений |

Устройство, никогда не подтверждённое сканом, выселяется после порога промахов чистых
сканов; устройство, чей random address сохранён, остаётся — выключенный из сети
светильник не фантом.

## Чего реестр не делает

- Не считает diff desired против applied — это оркестратор; и не публикует
  семантических DALI-команд.
- Не трогает провод DALI.
- Не применяет applied-факты, recall и наблюдения к runtime напрямую — только через
  проектор.
- Не выполняет I/O вне своего слайс-стора: гидрация на старте и сброс грязных слайсов —
  его внутренняя обязанность, а документ правил хранит rules runtime.
