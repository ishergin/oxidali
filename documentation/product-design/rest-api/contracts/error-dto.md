# Ошибки: формы и словарь кодов

Как ошибка выглядит на каждой поверхности и что значат общие коды. Клиент опирается
только на код, никогда на `message`.

**Границы:** продуктовые коды — enum `ErrorCode` в
`dali2rust-contracts::msg::errors`, его `rest_name()` задаёт написание для HTTP,
операций и WebSocket одновременно. Коды валидации HTTP-слоя — строки
`dali2rust-api`. Коды, специфичные для одного ресурса, и условия, в которых они
возникают, описаны в документе этого ресурса.

## Формы

| Поверхность | Форма |
|---|---|
| Ответ HTTP с ошибкой | `{"error": "<code>"}`, иногда с `"message"`. Плоская строка, а не объект. Парсер правил добавляет `line` / `column`. |
| Тело подтверждения диагностических `/dali/*` | Своя форма — [`../resources/diagnostic-dali.md`](../resources/diagnostic-dali.md) §Ответ. |
| Терминальная операция (`GET /operations/{id}`, канал WS `operations`) | `error: {code, message}`. `code` — из словаря ниже, `message` называет конкретную причину (`adapter_disabled`, `controller_passive`, `rule_set_conflict`, `below_device_minimum`, `transport_unsupported_24bit`, имя шага прошивки, …) и полезен оператору. |
| Состояние света (`state.error`) | `{code}` без текста. Доезжает только `device_absent` — [`state-contracts.md`](state-contracts.md) §`RuntimeObservation`. |
| WebSocket | `{"op": "error", "error": {"code", "message"}}` в ответ на кадр клиента. Отказ в подключении устройство выражает только CLOSE ([`../resources/websocket.md`](../resources/websocket.md)). |

## Общие коды HTTP

| Код | HTTP | Когда |
|---|---|---|
| `invalid_json` | 400 | Тело не разбирается как JSON или не объект там, где нужен объект. |
| `unknown_field` | 400 | Поле, которого у ресурса нет. |
| `invalid_resource_id` | 400 | Идентификатор в пути не число или вне своего диапазона (short address > 63, группа/сцена > 15, лампа > 63). Адаптер с несуществующим номером — `404 not_found`. |
| `empty_patch` | 400 | `PATCH` без единого поля там, где ресурс требует хотя бы одно. |
| `not_found` | 404 | Записи нет; для input devices и правил — свои `*_not_found`. |
| `method_not_allowed` | 405 | Метод не поддерживается маршрутом. |
| `conflict` | 409 | Конфликт состояния: вторая операция того же вида на адаптере (apply, commissioning), занятый целевой адрес, устройство уже привязано к другой лампе, адаптер выключен (`enabled: false`) на синхронном пути. |
| `superseded` | 409 | Синхронную команду вытеснила более новая команда той же цели до выхода на провод, и ни одно её поле в выжившую не перешло; команда, чьи поля перешли, подтверждается успехом ([коалесинг](../../../architecture/03-bus-and-backpressure.md)). Только для синхронных маршрутов; у операций вытеснение — это статус `cancelled`. |
| `controller_standby` | 409 | Контроллер пассивен и не ведёт шину; ответ несёт `Retry-After: 1` — [`../resources/redundancy.md`](../resources/redundancy.md). |
| `invalid_enum` | 422 | Значение не входит в enum. |
| `invalid_value` | 422 | Значение вне диапазона, неверного типа или противоречит другому полю тела. |
| `out_of_range` | 422 | Числовая настройка вне документированного диапазона (настройки redundancy, политики). |
| `unsupported_field` | 422 | Известное поле, которое здесь не пишется: read-only, runtime, derived или поле другого класса ресурса. |
| `unsupported_capability` | 422 | Цветовой режим, которого нет в effective capabilities цели. |
| `vl_unbound` | 422 | Виртуальная лампа оказалась без привязки к моменту исполнения. |
| `internal_error` | 500 | Внутренняя ошибка сборки ответа. |
| `commands_ingress_overload` | 503 | Входная очередь шины или инбокс владельца полон. Повторить. |
| `confirmation_slots_exhausted` | 503 | Заняты все слоты ожидания подтверждений. Повторить. |
| `partial_apply` | 503 | Многокадровая запись (несколько команд под одним дедлайном) опубликована не целиком. Поля идемпотентны, повтор безопасен. |
| `execution_failed` | 503 | Команда исполнена с отказом, и более точного кода нет: исчерпан бюджет повторов на занятой шине и т. п. Повтор безопасен — последовательности идемпотентны. |
| `confirmation_timeout` | 504 | Подтверждение не пришло в `confirmation_timeout_ms`. Команда не отозвана и может исполниться позже. |
| `apply_watch_timeout` | 504 | Запись подтверждена, но read-after-write не дождался применения. |

## Продуктовые коды операций

Появляются в `error.code` терминальной операции (и частично в подтверждениях).

| Код | Значение |
|---|---|
| `operation_failed` | Общий отказ операции; причина — в `message`. |
| `execution_failed` | Отказ исполнения без более точного кода (для прошивки `message` называет шаг). |
| `commands_ingress_overload` | Команда операции не была доставлена владельцу ([`operations.md`](../resources/operations.md) §Жизненный цикл). |
| `conflict` | Операцию отверг гейт: адаптер выключен (`message = adapter_disabled`), контроллер пассивен (`controller_passive`), обновление уже идёт. |
| `preempted` | Чтение или запись уступили более приоритетной команде (оператор тронул ползунок, пока шло чтение). **Штатный исход** механизма приоритетов, не отказ: поверхность не красит его как ошибку. |
| `device_absent` | На short address ничего нет: гир не ответил на `QUERY CONTROL GEAR PRESENT` за весь бюджет переспросов или замолчал посреди чтения ([`09`](../../../architecture/09-dali-protocol-rules.md) §Reading answers). Отдельно от транспортных отказов, потому что действия оператора противоположны. |
| `verify_failed` | Read-back проверенной записи ответил другим значением: запись не принята. |
| `verify_unanswered` | Read-back остался без ответа: взяла ли запись — неизвестно; подозрение на сам запрос (опкод или переменная, которых у устройства нет). |
| `verify_contended` | Read-back получил нарушающий кадр: несколько устройств ответили на один адрес — запись ушла неизвестно куда, искать дубль адреса. |
| `read_contended` | Нарушающий кадр при чтении во время скана: на сегменте дубль адреса, ничего не записывалось. |
| `vl_unbound` | Строка apply/лампа без привязки. |
| `registry_reset` | Причина отмены (`cancelled`) операций при перезагрузке состояния реестра. |
| `confirmation_timeout` | Этап операции не получил подтверждения. |

Коды кадров WebSocket (`invalid_channel`, `invalid_value`, `ws_clients_exhausted`) и
когда они приходят — [`../resources/websocket.md`](../resources/websocket.md).

## Правила расширения

- Новый код добавляется в `ErrorCode` только в конец (дискриминант — wire) и
  появляется здесь; написание существующих не меняется.
- Удаление кода, переименование или смена HTTP-статуса — новая мажорная версия API.
