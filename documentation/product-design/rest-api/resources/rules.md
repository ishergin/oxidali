# Ресурс: Rules

Документ правил автоматики: чтение, проверка, замена целиком, включение отдельного
правила и ручной запуск.

**Границы:** язык и словарь операций —
[`../../runtime-modules/rules-engine/operations.md`](../../runtime-modules/rules-engine/operations.md);
движок — [`../../runtime-modules/rules-engine/README.md`](../../runtime-modules/rules-engine/README.md);
решение о языке — [`ADR-016`](../../../architecture/decisions/ADR-016-input-devices-and-rule-engine.md).
BDD — [`rules`](../../../../tests/dali2rust-bdd/features/rules/).

## Документная модель

Набор правил — **один документ**, и его канон — исходный текст оператора: устройство
хранит байты как записано, с комментариями и форматированием. Отсюда форма ресурса:
правится документ целиком. Идентичность правила — его **имя**, уникальность проверяет
парсер; числовых id нет. Принтера «модель → текст» нет, поэтому типизированная
проекция — только для чтения.

Все тела — JSON в обе стороны. Заголовков `ETag` / `If-Match` нет: конкурентность
решает поле `base_revision` в теле `PUT`.

## Маршруты

| Метод | Путь | Назначение | Ответ |
|---|---|---|---|
| `GET` | `/api/v1/rules` | Документ: `lang_id`, `revision`, `diagnostic`, `rule_count`, `source` | `200` |
| `GET` | `/api/v1/rules?format=json` | Типизированная проекция скомпилированного набора | `200` |
| `POST` | `/api/v1/rules/parse` | Проверка без записи | `200` / `400` |
| `PUT` | `/api/v1/rules` | Заменить документ | `202` `config_write` |
| `PATCH` | `/api/v1/rules/{name}` | Только `enabled` | `200` |
| `POST` | `/api/v1/rules/{name}/run[?dry=1]` | Ручной запуск / сухой прогон | `202` `config_write` |

## Чтение

- `diagnostic` не `null`, когда хранимый документ не действует: не скомпилировался —
  при загрузке или после того, как имя цели перестало разрешаться в реестре (исходник
  тогда сохранён и перекомпилируется сам, когда имя вернётся), — или не загрузился
  целиком. Тогда `rule_count = 0` и движок не исполняет ни одного правила.
- `?format=json` кладёт скомпилированный набор под ключ `rules` целиком, поэтому
  правила лежат в `rules.rules`, а `def`-блоки — в `rules.blocks`. Каждая ссылка на
  сущность несёт `adapter_id`, даже если автор его не писал; `cooldown_ms` отдаётся уже
  разрешённым (с классовым значением по умолчанию); несколько `when` — массив
  триггеров со смыслом ИЛИ.
- Каждое правило несёт блок `runtime`: сколько раз и когда оно сработало последним и чем
  это кончилось (`ok`, `partial`, `failed`, `refused` с причиной). Блок живёт в RAM с
  загрузки контроллера, сухой прогон его не двигает, у несработавшего правила счётчик 0.
  Поток активаций — событие `RulesActivationEvent` на канале WS `rules`; агрегаты — блок
  `rules` в [`stats.md`](stats.md).

## `POST /rules/parse`

Тело `{"source": …}` не больше 12 240 байт. Ничего не публикует и не пишет: разбор
действующим компилятором плюс проверка имён целей против реестра — единственная
грамматика живёт на устройстве.

- `200 {"ok": true, "rules": [{name, enabled}…]}`.
- `400 {"error": "parse_error", "line", "column", "message"}` — координаты 1-based по
  присланному тексту; ради них маршрут и существует отдельно от `PUT`. Лимиты языка
  (число правил, развёрнутых действий, глубина) — тоже `parse_error` с координатами.

## `PUT /rules`

Тело `{"source": …, "base_revision": N}`, оба поля обязательны. Ревизия берётся из
`GET`; несовпадение — `409 rule_set_conflict`, иначе две вкладки редактора молча
затирали бы друг друга.

- Синтаксис проверяется дважды и намеренно: на httpd — быстрый `400` с координатами
  до публикации; на воркере при коммите — имена против свежего слепка реестра (между
  запросом и коммитом лампу могли переименовать).
- Ответ `202` + `operation_id` — чанковая запись
  ([`../stability-and-versioning.md`](../stability-and-versioning.md) §Дисциплины
  ответа): одна замена набора, одна ревизия, одно событие — или ничего.
- Отказ коммита (несовпадение числа чанков, проигранная гонка ревизий, превышенный
  лимит правил) оставляет на устройстве **прежний** документ.

## `PATCH /rules/{name}`

Тело `{"enabled": bool}` — единственное поле. Это переключение бита в манифесте
слайса, а не перезапись документа, поэтому ответ синхронный:
`200 {"name", "enabled"}` после сдвига ревизии. Модификатор `enabled false` в тексте
задаёт лишь начальное значение при коммите документа; дальше им владеет этот маршрут.
Бит хранится отдельно от скомпилированного набора и переносится на каждую
перекомпиляцию, в том числе после окна, когда документ не компилировался; сбрасывает
его только коммит документа. Переключение не перезагружает набор: ожидающие `wait` и
`after` других правил и биты, выставленные действиями `rule(...)`, его переживают.

Имя в пути доходит целым, с `+` и кириллицей: путь декодируется по правилам пути, а не
query string ([`04`](../../../architecture/04-contracts-and-api-bridge.md) §JSON
boundaries).

## `POST /rules/{name}/run`

Публикует ручной запуск и отвечает `202` + `operation_id`. Ручной запуск игнорирует
триггеры, но **не** условия; выключенное правило отказывает на воркере. `?dry=1` —
сухой прогон: движок вычисляет условия по текущему слепку, ничего не публикует на шину
и не влияет на `rule(…) fails`. Результат — событие активации с `dry: true` и счётчик
сухих активаций в статистике; синхронного ответа с «что бы сработало» нет, потому что
вычисление идёт на воркере правил, а не на задаче httpd.

## Ошибки

| Код | HTTP | Когда |
|---|---|---|
| `invalid_json` | 400 | Тело не JSON (в том числе `text/plain`) |
| `missing_source` | 400 | В `PUT` / `parse` нет строкового `source` |
| `missing_base_revision` | 400 | В `PUT` нет числового `base_revision` |
| `missing_enabled` | 400 | В `PATCH` нет булева `enabled` |
| `parse_error` | 400 | Синтаксис или неизвестное имя цели, с `line` / `column` / `message` |
| `rule_not_found` | 404 | Правила `{name}` нет в документе (`PATCH`, `run`) — до публикации |
| `rules_not_compiled` | 409 | `PATCH` по документу, который не скомпилировался |
| `rule_set_conflict` | 409 | `base_revision` не совпал с текущей ревизией |
| `rule_document_too_large` | 413 | Исходник больше 12 240 байт |
| `commands_ingress_overload` | 503 | Шина отказала в публикации |

Отказы, которые приходят через операцию: `run` по выключенному правилу, отказы
чанкового коммита.
