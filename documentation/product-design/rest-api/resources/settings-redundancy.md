# Ресурс: Settings — Redundancy

Что оператор настроил для пары контроллеров на одном сегменте: роль, параметры
обнаружения отказа пира и откуда тянуть конфигурацию.

**Границы:** что произошло (роль сейчас, переходы, плановое переключение) —
[`redundancy.md`](redundancy.md); механизм —
[`../../runtime-modules/redundancy/README.md`](../../runtime-modules/redundancy/README.md);
решение — [`ADR-018`](../../../architecture/decisions/ADR-018-controller-redundancy.md).
BDD — [`redundancy`](../../../../tests/dali2rust-bdd/features/redundancy/).

## Маршруты

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/api/v1/settings/redundancy` | `200` |
| `PATCH` | `/api/v1/settings/redundancy` | `200` — применённые настройки |

Controller-global; целевой адаптер — первичная шина. Настройки пишутся и на
стэндбае: иначе стэндбай нельзя было бы сделать первичным.

## Поля

| Поле | Значения | Смысл |
|---|---|---|
| `enabled` | bool, по умолчанию `false` | Пока `false`, ничего не зондирует и не перехватывает — поведение одиночного контроллера. |
| `role` | `primary` \| `standby` | `standby` — узел, который исполняет арбитраж (DiiA 351 тип B); `primary` — доминантный, не спрашивает и сам не уступает. Строка, а не флаг: у сторон разные алгоритмы. |
| `probe_interval_ms` | `250..60000`, по умолчанию 400 | Период зонда. Один зонд ≈ 38 мс активного провода, поэтому пол 250 мс — это уже ≈ 15 % шины. |
| `takeover_after_missed` | `1..5`, по умолчанию 2 | Подряд неотвеченных зондов до перехвата. По умолчанию не 1: потерянный запрос неотличим от ответа «нет». |
| `boot_listen_ms` | `0..120000`, по умолчанию 2000 | Сколько свежезагруженный контроллер слушает, прежде чем что-то занять. |
| `peer_device_short_address` | `0..63` \| `null` | Адрес пира как control device Part 103. Нужен только плановому переключению: зонд широковещательный. |
| `peer_url` | `http://host[:port]`, до 64 символов, `""` — выключено | Откуда пассивный контроллер тянет конфигурацию. Пустая строка — переноса нет, и стэндбай, взявший шину, не знает установки. На роль не влияет никак. |

Худший случай обнаружения отказа — `takeover_after_missed × probe_interval_ms` плюс один
обмен.

## Ошибки

| Код | Когда |
|---|---|
| `400 unknown_field` | Ключ вне списка. |
| `422 invalid_value` | `role` не `primary` / `standby` (неизвестная роль **не** откатывается к `primary`: два узла, откатившиеся оба, вели бы шину вдвоём); `peer_url` не `http://host[:port]` (молча понизить `https://` до HTTP или принять голое имя хоста хуже отказа); значение неверного типа. |
| `422 out_of_range` | Значение вне диапазона таблицы, включая `peer_url` длиннее 64 символов: обрезанный URL — это **другой** хост. |

Диапазоны на входе **отвергаются**, а при загрузке слайса — **зажимаются**: то, что
напечатал оператор, — ошибка, о которой стоит сказать; то, что лежит в слайсе, —
представление другой сборки о дефолтах, и контроллер, отказавшийся защищать шину из-за
числа из чужого слайса, хуже того, что зондирует с разумным периодом.
