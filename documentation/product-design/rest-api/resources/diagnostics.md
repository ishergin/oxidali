# Ресурс: Diagnostics

Сырой срез внутренних счётчиков рантайма по путям доставки и исполнения — для
отладки, а не для оператора.

**Границы:** продуктовая сводка — [`stats.md`](stats.md); смысл отдельного счётчика —
у его воркера в [`../../runtime-modules/`](../../runtime-modules/) и в коде. Форма —
`DiagnosticsDto` в `dali2rust-api`; её блоки, зеркало TypeScript, чтения HIL/BDD и
таблица ниже сверяются `scripts/verify_counter_surface.py` (по **именам блоков**), а
наличие каждого блока на экране — `scripts/verify_read_surface.py`. BDD —
[`diagnostic`](../../../../tests/dali2rust-bdd/features/diagnostic/).

## Маршрут

`GET /api/v1/diagnostics` → `200`, ответ стримится; не-`GET` — `405`. Собирается
композиционным мостом из удерживаемых счётчиков, без команд шины и без записей в
реестр. Тот же снимок каждые 2 с приходит на канал WebSocket `diagnostics`; куда идёт
новый счётчик — правило [`04`](../../../architecture/04-contracts-and-api-bridge.md)
§Counter surface.

## Как читать

- Счётчики и гейджи читаются по правилам [`stats.md`](stats.md) §Правила чтения.
- **Ноль у счётчика механизма не значит «здоров»**: счётчик повторов, который ни разу
  не сдвинулся, говорит лишь, что механизм не был достигнут.
- Часть счётчиков — работа механизма, а не отказ: уступка фона оператору, вытеснение,
  срабатывание стража устаревших наблюдений.
- `ignored_*` — кадры, пришедшие воркеру, но не относящиеся к нему.

Блоки:

| Блок | Содержимое |
|---|---|
| `uptime_ms` | Миллисекунды с монтирования HTTP-поверхности. |
| `bus` | Шина по каналам (команды, подтверждения, события): попытки публикации, поставленные в очередь, переполнения входа, отказы по размеру и виду; неразмаршрутизированные команды и потерянные синтетические отказы доставки; по каждому подписчику — доставлено и переполнения его инбокса. |
| `confirmation_bridge` | Подтверждения без зарегистрированного слота ожидания. |
| `dali_worker` | Отказы и аборты исполнения: невалидные команды, отказы, не опубликованные подтверждения и события (включая факты чтения — тогда реестр неверен, а операция отчиталась успехом); повторы гарантированной доставки и потраченное на них время; вытесненные target-state; аборты чтений по занятости и транспорту; уступки фона оператору; отсутствующие приборы; порванные последовательности перечисления типов; деградировавшие при скане приборы; неснятый health-probe; короткие чтения банков; сканы и адресация Part 103; кадры, подавленные пассивной ролью. |
| `sniffer_translator` | Чужие кадры: опубликованные наблюдения, нераспознанные (считаются, не публикуются), отслеживаемые special-команды и подготовленный цвет DT8, события Part 103 (типизированные, нетипизированные, схема 0, жизненный цикл), пары команд application controller. |
| `projector` | Проектор state-fanout: опубликованные runtime-обновления и их повторы, развёртки групп, сцен и broadcast, слитые и пропущенные наблюдения, отказы публикации. |
| `apply_orchestrator` | Прогоны apply: начатые, опубликованные ячейки и пропуски, повторы, таймауты исходов, ожидания места во входе шины, прогоны, прерванные трекером, неопубликованные терминальные сигналы. |
| `operations` | То, чего нет в `/stats`: истёкшие исходы без своей операции и проигнорированные кадры. |
| `registry` | Runtime-факты, отброшенные более свежим наблюдением того же прибора (работа стража, не отказ); неопубликованные сигналы конфигурационной записи (единственное здоровое значение — ноль: иначе операция кончится таймаутом на успехе). |
| `persistence` | Сбросы слайсов (успех, ошибка, нет места) и гидратация (загружено, по умолчанию, ошибка). |
| `phy_sniffer` | Кумулятивно по сниффу PHY: кадры по ширине, ошибки декодирования, неподдерживаемая длина, потери, быстрые опросы. |
| `dali_wire` | Провод как таковой: транзакции (начатые, завершённые, по классам, переоткрытые, превышения бюджета, утечки), кадры по приоритетам и поздние окна приоритета 1, аренда шины, коллизии и чужие кадры в окне, повторы обменов, пары send-twice, состояния отказа питания шины и system failure, **занятость провода** в тиках прерывания и её гейдж в промилле ([08](../../../architecture/08-dali-phy-and-transport.md) §Wire counters). Отказы здесь — только превышение бюджета транзакции и утечки; остальное — работа механизма. |
| `hcl` | Планировщик HCL: тики (и тики без часов), опубликованные и отброшенные по пределу кадры, таймауты и отказы команд, отказы входа шины, приостановки (начатые, снятые в полночь, снятые досрочно). |
| `poller` | Поллер: циклы (считаются и при выключенном), опубликованные, завершённые, отказавшие, уступившие и «отсутствующие» чтения, неприсланные исходы, придержанная работа (бюджет провода, окно тишины, недобранный цикл), исключённые цели (гейдж), cooldown'ы, исходы health-probe. |
| `websocket` | Клиенты (гейдж), отправленные, потерянные и слитые кадры, переполнения инбокса воркера (теряют все), отказанные апгрейды (сверх капа или чужой `Origin` — работа предела), записи сниффера и строки лога. |
| `mqtt` | Мост: подключён ли, подключения, публикации и отказы, принятые, отброшенные и неразмаршрутизируемые команды, discovery, терминальные события (отказы и повторы), выброшенные и слитые события шины, публикации правил, срезанные ограничением частоты. |
| `rules` | Воркер правил: применённые и отвергнутые коммиты документа, переключения, отказы гидратации и персиста, опубликованные и отвергнутые эффекты, эффекты по тёмной лампе, глаголы без шинного носителя, строки лога и статистики правил, активации. |
| `redundancy` | Отвечающая сторона пары: лиза продлена (супервизор жив), наблюдаемый воркер встал, чужие зонды отвечены в окне, подавлены, не ушли (ячейка PHY занята, шина ожила, окно закрылось), поздние ответы, наши зонды, не дошедшие до провода, неполное плановое переключение. |

## Health-probe (`poller.health_probes_*`)

Широковещательный вопрос поллера «есть ли где-то отказ лампы» с положительным контролем —
механизм в [`09`](../../../architecture/09-dali-protocol-rules.md) §Reading answers,
расписание и бюджет — у [поллера](../../runtime-modules/poller/README.md). Исходы:

| Исход | Смысл |
|---|---|
| `invalid` | Контроль не ответил — измерение недействительно, «чисто» не утверждается. |
| `clear` | Тишина в ответ на запрос отказа при ответившем контроле: отказов нет. |
| `one_failure` | Чистый ответ: **не меньше одного** прибора с отказом лампы. |
| `several_failures` | Нарушающий кадр: отвечали несколько приборов — нарушение в окне ответа само является ответом. |
| `expired` | Результат не вернулся за окно охраны. |
