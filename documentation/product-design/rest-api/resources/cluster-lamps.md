# Ресурс: Cluster — лампы узлов

Лампы всех узлов кластера: свои из реестра, чужие из кэша, и команда одной лампе.

**Границы:** остальной ресурс кластера — [`cluster.md`](cluster.md); что делает кластер и
почему — [`../../runtime-modules/cluster/README.md`](../../runtime-modules/cluster/README.md)
и [ADR-035](../../../architecture/decisions/ADR-035-cluster-of-installations-over-udp.md).
BDD — [`cluster`](../../../../tests/dali2rust-bdd/features/cluster/).

## Маршруты

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/api/v1/cluster/lamps` | `200` — `{"nodes": [...]}`: сводка ламп узлов |
| `GET` | `/api/v1/cluster/nodes/{node}/lamps` | `200` — `{"node", "source", "lamps": [...]}` |
| `GET` | `/api/v1/cluster/nodes/{node}/lamps/{lamp}` | `200` — лампа узла |
| `PUT` | `/api/v1/cluster/nodes/{node}/lamps/{lamp}/target-state` | `200` — команда лампе: у этого узла — лампа, у другого — `{"correlation_id", "status": "sent"}` |

## Лампы узлов

Узел, который держит номер, объявляет состояние своих ламп и своих частей каналов и
сведения о своих лампах, каждое своим набором страниц на адаптер: состояние — после
изменения, собранного за короткое окно, сведения — после переименования или привязки, оба —
по периодическому обновлению и в ответ на hello нового соседа. Набор, который отличается от
прежнего только возрастом наблюдений, не уходит. Принятые наборы лежат в том же кэше, что
и сведения узлов, по тем же правилам: показывается только целый набор, новая плата на
номере узла сразу заменяет старую, Forget и сброс кэша убирают и лампы.

Лампа другого узла появляется в списке, когда пришли сведения о ней: без них её
возможности неизвестны, и состояние одно её не показывает. Лампа узла устаревает, когда её набор состояния старше трёх периодов обновления, когда
присутствие не показывает узел живым или когда узел слышен с другой платы; первый пульс
платы после её перезагрузки сразу убирает её прежние лампы. Устаревшая
лампа остаётся в списке с `source: "stale"`, а её состояние показывается неизвестным —
`power: "unknown"`, `level: null`, — а не последним услышанным.

`GET /api/v1/cluster/lamps` — `{"nodes": [...]}`: строка этого узла и строка каждого узла,
чьё состояние или сведения о лампах приняты. Тот же ресурс несёт кадр `ClusterLamps` канала
`cluster`, когда лампы или их свежесть меняются ([`websocket.md`](websocket.md)); сами лампы
клиент читает по REST.

| Поле | Смысл |
|---|---|
| `node`, `source` | Как в сведениях узлов ([`cluster.md`](cluster.md) §Сведения узлов). |
| `lamps` | Сколько ламп узла в списке. |
| `state_set`, `info_set` | Номера показанных наборов состояния и сведений; у этого узла `null`. |
| `age_ms` | С приёма последней страницы состояния; у этого узла `null`. |
| `sequence_gaps` | Пропуски номеров последовательности у платы узла по присутствию — видимая потеря кадров; `null`, если узел слышен с другой платы, и у этого узла. |

`GET /api/v1/cluster/nodes/{node}/lamps` — лампы узла по возрастанию номера, по одной
сериализуемой за раз; свои из реестра, чужие из кэша. `GET …/lamps/{lamp}` — одна лампа.
Лампа имеет форму ресурса виртуальной лампы ([`virtual-lamps.md`](virtual-lamps.md)) и ещё:

| Поле | Смысл |
|---|---|
| `cluster_address` | `{"node", "adapter", "lamp"}` — адрес лампы в кластере. |
| `source` | `own`, `cached` или `stale`. |
| `bound` | Привязана ли лампа к прибору; физический адрес остаётся на узле. |
| `observation_age_ms` | Возраст наблюдения уровня: у чужой лампы — возраст у владельца плюс время с приёма; `null`, если уровень неизвестен. |
| `home_assistant` | `{"unique_id", "discovery_topic"}` сущности лампы у владельца; `null`, если сущности нет или владелец не назвал себя. |

## Команда лампе

`PUT /api/v1/cluster/nodes/{node}/lamps/{lamp}/target-state` — команда одной лампе. Тело —
то же, что у `target-state` виртуальной лампы ([`virtual-lamps.md`](virtual-lamps.md)):
уставка или `recall`; `dim` отвергается, как там. Номер этого узла — это маршрут
виртуальной лампы `0` с его ответами и ошибками, и в сеть ничего не уходит. Лампу другого
узла узел сверяет с её сведениями в кэше до отправки: цвет — с её возможностями, как
маршрут виртуальной лампы, — и шлёт кадр дважды с одним номером последовательности.
Исполняет его только узел лампы, если он принимает одиночные лампы
(`accept_single_lamps`); ответ `200` значит, что кадр ушёл в сеть. У лампы своя очередь и
свой потолок, как у канала.
Отказы режима узла — выключенный кластер, нет адреса, узел не работает, резервная плата —
те же, что у команды каналу ([`cluster.md`](cluster.md) §Ошибки).

## Ошибки

| Случай | Ответ |
|---|---|
| Лампы узла, который не этот и чьих ламп нет в кэше; лампа, которой узел не показывает | `404 not_found` |
| Номер узла вне `0..7` или лампы вне `0..63` в пути ламп | `400 invalid_resource_id` |
| Команда лампе другого узла, которой нет в кэше | `404 not_found` |
| Команда лампе другого узла, чьи сведения устарели | `409 conflict`, `message: cluster_lamp_stale` |
| Команда лампе другого узла, не привязанной к прибору | `409 conflict`, `message: cluster_lamp_unbound` |
| Цветовой режим, которого у лампы другого узла нет | `422 unsupported_capability` |
| `dim` в команде лампе | `422 unsupported_field` |
