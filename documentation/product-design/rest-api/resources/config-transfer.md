# Ресурс: Config transfer

Перенос конфигурации между контроллерами и её резервная копия: слайсы хранилища как
байты.

**Границы:** формат и хранение слайсов —
[`../../../architecture/06-registry-and-persistence.md`](../../../architecture/06-registry-and-persistence.md);
автоматическое вытягивание конфигурации стэндбаем —
[`../../runtime-modules/redundancy/README.md`](../../runtime-modules/redundancy/README.md).
BDD — [`config_transfer`](../../../../tests/dali2rust-bdd/features/config_transfer/).

Runtime-состояние проецируется с провода, **конфигурация реплицируется**
([`ADR-018`](../../../architecture/decisions/ADR-018-controller-redundancy.md)): сниффер
не несёт ни имён, ни привязок, ни определений групп, ни расписаний, ни правил.

## Маршруты

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/api/v1/config/slices` | `200` — манифест: какие слайсы есть и сколько занимают |
| `GET` | `/api/v1/config/slices/{slice}` | `200`, `application/octet-stream` — слайс ровно как во флеше (с версией и конвертом) |
| `PUT` | `/api/v1/config/slices/{slice}` | `200` — манифест после замены слайса и перечитывания реестра |

Чтения работают в обеих ролях: стэндбай обязан уметь сказать, что у него есть.

## Что переносится

Настройки контроллера (часовой пояс, по которому идут расписания; слайс первый в
манифесте и в порядке гидратации), расписания HCL, настройки поллера, политики,
настройки Home Assistant — вместе с паролем брокера, по решению владельца для
доверенной LAN ([`ADR-018`](../../../architecture/decisions/ADR-018-controller-redundancy.md)),
устройства ввода, документ правил и по каждому адаптеру — физические устройства,
группы, виртуальные лампы и сцены. Стэндбай, взявший шину, объявляет в Home Assistant ту
же установку: мост работает только в активной роли
([redundancy](../../runtime-modules/redundancy/README.md) §Пассивный контроллер).

Не переносятся, и отказ живёт в самом разрешении имени слайса, чтобы о нём не нужно
было помнить вызывающему:

| Слайс | Почему |
|---|---|
| адаптеры | Сколько у коробки шин и как они названы — свойство коробки, а не установки. |
| настройки DALI | Несут `application_active` и собственный адрес control device: скопировать — значит отдать стэндбаю роль первичного и его адрес. |
| настройки redundancy | Роль пира — не то, что пир получает копией. |

## Импорт

- Манифест и импорт идут в порядке гидратации: **физические устройства раньше
  привязок** ([`06`](../../../architecture/06-registry-and-persistence.md) §Versions).
- Байты пишутся прямо в хранилище под тем же замком, что и сброс слайсов, — у записей
  в хранилище один порядок; по шине идёт только команда перечитывания к единственному
  писателю реестра ([`../../bus-contracts/commands.md`](../../bus-contracts/commands.md)
  §Вне шины).
- Перечитывание — **полное**, по всему хранилищу: частичная перезагрузка виртуальных
  ламп осиротила бы привязки. Имя слайса в команде — для лога.

| Код | Когда |
|---|---|
| `404 not_found` | Имя не разрешается в переносимый слайс. |
| `409 persistence_disabled` | Хранилище слайсов не подключено в этой сборке. |
| `422 empty_slice` | Пустое тело. |
| `503 store_failed` | Хранилище отказало в записи. |
| `503` / `504` после записи | Байты **уже во флеше**, но живой реестр не перечитался; следующая загрузка их подхватит. Отказ сообщается, а не проглатывается. |
