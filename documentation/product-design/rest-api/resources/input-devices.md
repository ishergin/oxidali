# Ресурс: Input devices (IEC 62386-103)

Управляющие устройства DALI-2 — кнопочные панели, датчики присутствия и освещённости:
скан, коммиссионинг, конфигурация инстансов и индикации, метаданные и выставление в
Home Assistant.

**Границы:** поведение устройств и модуля («модуль» ниже) —
[`../../runtime-modules/input-devices/README.md`](../../runtime-modules/input-devices/README.md);
потребитель событий — [`rules.md`](rules.md); события в реальном времени — канал WS
`input` ([`websocket-payloads.md`](websocket-payloads.md)). BDD —
[`input_devices`](../../../../tests/dali2rust-bdd/features/input_devices/).

`{short_address}` здесь — адрес в собственном пространстве устройств ввода, а не адрес
control gear ([09 §Part 103](../../../architecture/09-dali-protocol-rules.md#part-103-control-devices)).

## Маршруты

| Метод | Путь (`/api/v1/adapters/{adapter_id}/input-devices/…`) | Назначение | Ответ |
|---|---|---|---|
| `GET` | `` (коллекция) | Список устройств (сводка) | `200` |
| `GET` | `{short_address}` | Устройство с инстансами | `200` |
| `PATCH` | `{short_address}` | `name`, `notes`, `ha_expose` | `200` |
| `DELETE` | `{short_address}` | Забыть запись реестра | `200 {"forgotten": true}` |
| `POST` | `scan` | Перечислить устройства на шине | `202` `discovery` |
| `POST` | `commission` | Назначить адреса | `202` `commissioning_address_change` |
| `POST` | `{short_address}/identify` | Опознать устройство | `202` `commissioning_identify` |
| `PATCH` | `{short_address}/instances/{n}` | Конфигурация инстанса на устройстве | `202` `config_write` |
| `PATCH` | `{short_address}/instances/{n}/feedback` | Индикация (Part 332) | `202` `config_write` |

`scan` не открывает сессию `INITIALISE` и безопасен на живой шине. `commission` с
пустым телом адресует только устройства без адреса; `{"include_addressed": true}` —
переадресация работающего сегмента, разрушительный вариант, который надо попросить
явно. Commissioning держит шину целиком, как и у control gear.

## Список и деталь

Список — сводка на устройство, деталь — отдельный ресурс: ответ строится на стеке
единственной задачи httpd, и все инстансы всех устройств в одном ответе туда не
помещаются.

- `instance_count` — сколько инстансов объявило устройство; деталь может показать
  меньше, если перечисление ещё не прочитало все. `first_instance_type` в строке списка
  называет, что это за устройство, или `null`, пока не прочитано.
- Значения, прочитанные с устройства, — пары `{value, read_at_ms}`; `{null, null}`
  значит «не читалось с этой загрузки»: таймеры и прочие переменные Part 333 не
  персистятся ([модуль](../../runtime-modules/input-devices/README.md) §Реестр и персист).
- `event_scheme_confirmed` — прочитанная схема событий равна 2; `false` — схема ещё не
  прочитана или другая. В схеме 0 события приходят **без идентичности источника**, и
  правила по конкретной панели перестают срабатывать.
- `manual_config_active: true` — переменные под локальным управлением устройства (Part
  333): наши записи будут **молча отброшены**, и «сохранено» показывать нельзя.
- `nvm_settling_until_ms` — до этого момента последняя конфигурационная запись может не
  пережить передёргивания питания (выдержка NVM — модуль §Коммиссионинг и
  конфигурация). Сравнивать с `now_ms` ответа.
- `feedback`: `probed: false` — индикацию ещё не пробовали; `present` — вердикт пробы;
  `opcode_map` — какой из двух карт запросов 332 отвечает устройство (`diia_corrected`
  или `ed1`; модуль §Индикация). Значения индикации — `null`, пока их не прочитала
  конфигурационная запись.
- `runtime` — последнее событие, его время, счётчик и текущее значение входа для
  датчиков (сырые единицы); не персистится.

## `PATCH …` — метаданные

`name` (`null` очищает), `notes` (отдельная команда шины: вместе поля не помещаются в
кадр), `ha_expose`. Пустое тело — `400 empty_patch`; не строка и не bool — `422
invalid_value`. Ответ — деталь после применения.

## `PATCH …/instances/{n}`

Поля (все необязательны, пустое тело — `400 empty_patch`): `event_scheme` (`0..4`),
`event_priority` (`3..5`), `enabled` (bool), `event_filter` (до трёх байт фильтра
событий), `instance_groups` (до трёх, `0..31` или `null` — не состоит), `timers`
(`t_short_ms`, `t_double_ms`, `t_repeat_ms` — кратно 20 мс, `t_stuck_s`).

- Каждое поле — отдельная 24-битная запись **с обязательным чтением обратно**:
  устройство молча игнорирует значения вне своего диапазона и все записи под локальным
  управлением.
- Таймеры проверяются статически на входе (`422 invalid_timer_range` — вне таблицы
  стандарта или не кратно шагу); ROM-минимумы устройства читаются на проводе перед
  записью, и значение ниже них завершает операцию с `message = below_device_minimum`.
- Приоритет события `2` запрещён: стандарт оставляет этот слот контроллеру.
- Включение двойного нажатия (`t_double_ms > 0`) — решение с ценой
  ([`../../runtime-modules/rules-engine/operations.md`](../../runtime-modules/rules-engine/operations.md)
  §1.1).

## `PATCH …/instances/{n}/feedback`

`timing`, `active_brightness`, `active_colour`, `inactive_brightness`,
`inactive_colour` — NVM-конфигурация индикации. Цвет — `1..63`
(`422 invalid_feedback_colour`); устройство, у которого проба не нашла индикацию
ни в одной карте, — `422 feedback_not_supported` (если проба ещё не выполнялась,
исполнитель пробует сам). Запись может изменить индикацию и соседних инстансов, поэтому
после неё перечитывается индикация всего устройства (модуль §Индикация).

Включать и выключать свечение через REST нельзя: это runtime-эффект, которым владеет
движок правил, и второй способ создал бы два источника истины о состоянии индикации.

## `POST …/identify`

Устройство без излучателя вправе не поддерживать `IDENTIFY DEVICE`; тогда операция
завершается отказом, а не молчаливым успехом. Надёжный способ опознать панель —
«нажмите кнопку»: событие приходит с адресом источника.

## Ошибки

| Код | HTTP | Когда |
|---|---|---|
| `invalid_resource_id` | 400 | Адрес или номер инстанса в пути не число |
| `input_device_not_found` | 404 | Адреса нет в реестре |
| `instance_not_found` | 404 | Инстанс вне объявленных |
| `empty_patch` | 400 | Тело без полей |
| `invalid_value`, `invalid_timer_range`, `invalid_feedback_colour`, `feedback_not_supported` | 422 | См. выше |

На транспорте без 24-битного пути (хост-мок) операции Part 103 завершаются с
`message = transport_unsupported_24bit`.
