# Ресурс: Virtual lamps

Пользовательская сущность UI и Home Assistant поверх физического прибора: 64 слота
`0..63` на адаптер, которые привязываются к прибору, отвязываются и перепривязываются.

**Границы:** сам прибор, его override'ы и заявления о возможностях —
[`physical-devices.md`](physical-devices.md); формы состояния и тела target-state —
[`../contracts/state-contracts.md`](../contracts/state-contracts.md); цепочка
target-state — [`../workflows.md`](../workflows.md); публикация в Home Assistant —
[`../../runtime-modules/mqtt-home-assistant/README.md`](../../runtime-modules/mqtt-home-assistant/README.md).
BDD — [`virtual_lamps`](../../../../tests/dali2rust-bdd/features/virtual_lamps/).

## Маршруты

| Метод | Путь (`/api/v1/adapters/{adapter_id}/virtual-lamps/…`) | Назначение | Ответ |
|---|---|---|---|
| `GET` | `` (коллекция) | Существующие записи ламп | `200` |
| `GET` | `{lamp_id}` | Одна лампа | `200` |
| `PATCH` | `{lamp_id}` | `name`, `ha_entity_enabled` | `200` |
| `PUT` | `{lamp_id}/binding` | Привязать / перепривязать | `200` |
| `DELETE` | `{lamp_id}/binding` | Отвязать | `200` |
| `DELETE` | `{lamp_id}` | Удалить запись лампы | `204` |
| `PUT` | `{lamp_id}/target-state` | Управление светом | `200` |

`lamp_id` вне `0..63` — `400 invalid_resource_id`. `GET` любого слота в диапазоне
отвечает `200`: слот без записи читается как пустая непривязанная лампа. Запись
появляется с первой привязкой или правкой метаданных.

## Наследование от прибора

У лампы нет собственных объявлений типа и цветового режима: `device_type_effective`,
`color_mode_effective`, их `*_source`, `capabilities` и `color_temperature_range` —
проекция привязанного прибора, включая то, что значение пришло из override'а
(`manual_override`). Непривязанная лампа не наследует ничего: `unknown` /
`discovered`, все capabilities `false`, состояние пустое. `binding` отсутствует в JSON,
когда привязки нет.

## `PATCH`

Merge-patch: `name` (1..64 байта) и `ha_entity_enabled`. Всё остальное, что есть в
DTO, — `422 unsupported_field`; неизвестный ключ — `400 unknown_field`. На провод
ничего не уходит; мост Home Assistant переобъявляет сущность лампы по событию
изменения.

## Привязка

`PUT …/binding` с телом ровно `{"physical_short_address": N}` (иначе `400
unknown_field`) — первая привязка или перепривязка; реестр коммитит, ответ —
обновлённая лампа.

- **Один прибор — одна лампа**: прибор, который держит другая лампа этого адаптера, —
  `409 conflict`. Привязка не отбирается молча: оператор сначала отвязывает ту лампу.
  Прибор, которого нет в реестре, — тоже `409 conflict`; адрес вне `0..63` — `422
  invalid_value`.
- HA `unique_id` лампы не зависит от привязки и переживает перепривязку.
- При смене прибора `desired`-членство в группах, которое было лишь принято из
  readback прошлого прибора, забывается (заданное оператором остаётся), а пока
  оператор не выразил намерения, членство нового прибора принимается как `desired` —
  иначе свежая лампа была бы «грязной» с рождения.
- `DELETE …/binding` снимает привязку и **сохраняет** конфигурацию лампы — так лампу
  переводят на заменённый светильник. Идемпотентен.
- Команды на провод не отправляются.

## `DELETE …/{lamp_id}` — удалить запись

Исчезает всё: имя, HA-опция, привязка, строка `desired` в матрице групп, строки во
всех шестнадцати сценах. Ответ `204`, записи нет — `404`. На провод ничего не
отправляется: членство и сцены, запрограммированные в приборе, остаются — кому нужен
чистый прибор, сначала снимает группы и сцены обычным путём. Событие изменения
публикуется, чтобы проекции (включая HA discovery) узнали об исчезновении.

## `PUT …/target-state`

Синхронное подтверждение, ответ `200` с обновлённой лампой. Операции не создаёт.

- **Непривязанная лампа — сознательный no-op**: `200` с текущей лампой, ничего не
  публикуется.
- Тело валидируется против effective capabilities лампы; публикуется команда со
  scope `VirtualLamp`, и worker разрешает адрес **в момент исполнения** — перепривязка
  на лету безопасна; лампа, отвязанная к этому моменту, — `422 vl_unbound`.
- Остальная цепочка — [`../workflows.md`](../workflows.md) §Target-state; ошибки тела —
  [`../contracts/state-contracts.md`](../contracts/state-contracts.md), коды исполнения
  (`409 superseded`, `503 execution_failed`) —
  [`../contracts/error-dto.md`](../contracts/error-dto.md).
