# Ресурс: HCL schedules

Расписания human-centric lighting: суточная кривая уровня и цветовой температуры для
групп и broadcast на одном или нескольких адаптерах, плюс приостановка расписания
ручным управлением.

**Границы:** исполнение (тик, интерполяция, астрономия, override, пейсинг) —
[`../../runtime-modules/hcl-scheduler/README.md`](../../runtime-modules/hcl-scheduler/README.md);
часы и часовой пояс — [`controller.md`](controller.md) §`/time`. BDD —
[`hcl`](../../../../tests/dali2rust-bdd/features/hcl/).

Расписание **cross-adapter** (его цели перечисляют адаптеры), поэтому маршруты не
вложены в `/adapters/{adapter_id}`. Расписания персистятся своим слайсом.

## Маршруты

| Метод | Путь | Назначение | Ответ |
|---|---|---|---|
| `GET` | `/api/v1/hcl-schedules` | Список | `200` |
| `GET` | `/api/v1/hcl-schedules/{schedule_id}` | Одно расписание | `200` |
| `POST` | `/api/v1/hcl-schedules` | Создать | `202` `config_write` + `schedule_id` |
| `PATCH` | `/api/v1/hcl-schedules/{schedule_id}` | Изменить (merge-patch) | `202` `config_write` |
| `DELETE` | `/api/v1/hcl-schedules/{schedule_id}` | Удалить | `204` |
| `GET` | `/api/v1/hcl-schedules/{schedule_id}/override` | Приостановлено ли расписание | `200` |
| `DELETE` | `/api/v1/hcl-schedules/{schedule_id}/override` | Снять приостановку досрочно | `204` |

## Модель расписания

- `schedule_id` — slug `[a-z0-9_-]{1,32}`; при `POST` задаётся клиентом или
  генерируется сервером.
- `enabled`, `active_days` (1..7 различных дней `mon`…`sun`), `algorithm`:
  `stepped` — значения точки держатся до следующей; `interpolated` — уровень и
  температура плавно ведутся между соседними точками.
- `location` (`latitude_deg`, `longitude_deg`) — обязателен, если хоть одна точка
  отсчитывается от восхода или заката.
- `targets` (1..16): `{adapter_id, scope: group | broadcast, group_ids?}`. Виртуальные
  лампы и сцены целями HCL не бывают. Существование адаптера не проверяется: цель на
  отсутствующем адаптере планировщик пропускает со счётчиком, не останавливая
  расписание.
- `points` (1..24): `time_ref` (`absolute` — минуты от локальной полуночи `0..1439`;
  `sunrise` / `sunset` — смещение `-720..720`), `level_mode`, `level`,
  `color_temperature_kelvin` (`null` — температуру не трогать). Пара `(time_ref,
  offset_minutes)` в расписании уникальна.
- `level_mode`:
  - `absolute` — точка задаёт уровень `0..254` (`0` — выключить), поле `level`
    обязательно;
  - `last_active` — прибор включается на свой сохранённый `lastActiveLevel`: яркость
    остаётся той, что выставил человек, а температура следует кривой; `level`
    запрещён;
  - `none` — уровень не трогается, выключенные лампы остаются выключенными; только
    температура; `level` запрещён.
- Полей плавности нет: плавность задаёт fade time прибора, как и у target-state
  ([`../contracts/state-contracts.md`](../contracts/state-contracts.md) §Тело target-state).

## Запись

`POST` и `PATCH` валидируют тело целиком и отвечают `202` + `operation_id` — чанковая
запись ([`../stability-and-versioning.md`](../stability-and-versioning.md) §Дисциплины
ответа). Тело `202` у `POST` дополнительно несёт `schedule_id` — это единственное
место, где клиент узнаёт сгенерированный id.

- **`409 conflict` значит «id занят», а не «расписание читается».** Между `202` и
  коммитом последнего чанка расписание невидимо для `GET`, но имя уже занято; проверка
  идёт по занятости, поэтому два быстрых `POST` не получат один сгенерированный id.
  Брошенная серия освобождает имя через 15 с.
- `PATCH` — merge-patch; массивы (`active_days`, `targets`, `points`) заменяются
  целиком; `schedule_id` не меняется.
- `DELETE` — синхронное подтверждение, `204`.
- Изменение расписания не снимает уже поднятую приостановку: правка соседнего поля не
  должна молча отменять ручное управление светом.

| Нарушение | Ответ |
|---|---|
| Неизвестное поле | `400 unknown_field` |
| `schedule_id` не slug | `422 invalid_resource_id` |
| Цель `virtual_lamp` / `scene` | `422 unsupported_field` |
| Неизвестный `algorithm`, `scope`, `time_ref`, `level_mode`, день недели | `422 invalid_enum` |
| Пустые или сверх лимита `targets` / `points` / `active_days`; `group` без `group_ids` или `broadcast` с ними; группа > 15; координаты вне диапазона; астрономическая точка без `location`; смещение вне диапазона; `level` не по правилу `level_mode`; дубль `(time_ref, offset_minutes)`; кельвины вне `1000..20000` | `422 invalid_value` |

## Под-ресурс `/override`

Ручное управление приостанавливает расписание по цели до локальной полуночи; что
считается ручным управлением и по какой цели — правило планировщика
([`hcl-scheduler`](../../runtime-modules/hcl-scheduler/README.md) §Override).

- `GET`: `suspended`, список приостановленных целей (`group_id` — только у
  `scope: group`) и `since_local_minutes` — с какой локальной минуты расписание
  перестало вести цель (нет поля, когда не приостановлено).
- `DELETE` снимает все флаги расписания через шину и отвечает `204`; нечего снимать —
  тоже `204`.
- Неизвестный `schedule_id` — `404` на обоих методах: `suspended: false` для
  несуществующего расписания читался бы как «работает».
- Это отдельный под-ресурс, а не поле расписания: флаги — volatile-состояние
  планировщика, а тип расписания служит базой merge-patch, и read-only поле в нём
  стало бы записываемым.
